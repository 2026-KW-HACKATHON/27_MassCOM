# 앱·시연 웹 파란 UI 일관화 설계

상태: 구현 기준 · 2026-09-24 · [Issue #142](https://github.com/2026-KW-HACKATHON/27_MassCOM/issues/142)

## 의도와 범위

사용자의 “바꾼 UI 기준으로 전부 완료·검증” 요청을 PR #138의 개발용 역할 선택 시안을 시각 기준으로 삼아 해석한다. 색상 선택 질문의 답변은 아직 없어 **파란 시안 기준을 잠정 채택**한다. 답변이 오면 코드 변경 전에 이 결정을 다시 확인한다. 목표는 운영 네 탭, 보조 화면, 개발용 시안과 읽기 전용 시연 웹이 서로 다른 프로젝트처럼 보이지 않는 것이다. 라우트·기능·인증·지갑·점주 권한·서버 데이터는 바꾸지 않는다.

## 시각 언어

지역 음식 탐색은 담백한 흰 바탕과 한눈에 읽히는 제목으로 시작한다. 파랑은 행동·선택·진행 상태에만 사용하고, 가상 점포 고지·성공·오류·NFT 상태 의미는 파랑 하나로 합치지 않는다. 새 사진·마스코트·가짜 점포·수집 실적은 추가하지 않는다.

| 역할 | 라이트 | 다크 |
| --- | --- | --- |
| 배경 | `#FFFFFF` | `#14171D` |
| 표면·카드 | `#F5F7FA` | `#20252F` |
| 본문 | `#192331` | `#F3F5F9` |
| 보조 본문 | `#58677D` | `#A6B0C0` |
| 행동 파랑 | `#2456D6` | `#9BB8FF` |
| 행동 연한 면 | `#EBF1FF` | `#25334F` |

`#2456D6`은 시안의 `#376CF4`보다 어둡다. 연한 파란 배경 위 일반 글자와 흰 버튼 글자의 4.5:1 대비를 먼저 확보하기 위한 조정이다. 오류·성공 의미색은 기존 `palette.ts`의 역할을 보존하고 별도 대비 시험으로 확인한다. 음식·보상 보조 표식에는 기존 따뜻한 황색 accent 면을 소량 유지한다.

## 토큰·컴포넌트 계약

- 기존 `apps/mobile/src/theme/palette.ts`와 `ui-metrics.ts`를 정본으로 유지한다. 새 독립 테마를 추가하지 않는다. `foundation.ts`는 정본 팔레트에서 시안에 필요한 이름만 매핑한다.
- 네 탭은 현재 20dp 페이지 여백·24dp 섹션 간격·20dp 카드 반경·48dp 최소 터치를 유지한다. 제목 24–28dp, 본문 14–16dp를 기본 계층으로 삼되 긴 한국어 문장과 200% 글씨에서 콘텐츠가 잘리면 더 작은 폰트로 숨기지 않고 줄바꿈·높이를 늘린다.
- `theme/colors.ts`의 Android dynamic wallpaper 색은 현재 운영 팔레트와 섞여 있다. 네 탭 `merchant-list`·`claim-redeem`·`collection`·`account-settings` 및 보조 `merchant-detail`·`merchant-claim`·`recommendations`·`auth-required`·`demo-configuration-required`·`wallet-link/index`·`wallet-link/configuration-required` **11개 화면 파일**의 사용자에게 보이는 배경·본문·버튼·상태면을 `colorsForScheme(useColorScheme())`의 동일한 의미색으로 옮긴다. `CenteredState` 같은 하위 컴포넌트도 빠뜨리지 않는다. 시스템 라이트↔다크 전환 뒤 같은 화면이 다시 렌더되는지 확인한다. 개발용 시안과 운영 화면에 서로 다른 파란 색상을 두지 않는다.
- 공용 버튼/카드는 두 화면 이상에서 구조와 상태가 실제로 반복될 때만 추출한다. 기존 `@expo/ui`/`Pressable`을 재사용하고 새로운 라이브러리·폰트·이미지 자산은 추가하지 않는다.
- 시연 웹 `apps/showcase-web/assets/showcase.css`는 앱의 라이트/다크 의미색을 정적 CSS 변수에 대응시킨다. 읽기 전용·가상 데이터 고지·키보드 초점·외부 자산 없음·쓰기 금지는 그대로 둔다.

## 상호작용·오류 경계

기본 탭과 음식점 상세·추천·방문 인증·도감·설정·지갑 진입은 유지한다. 로딩/빈 상태/오류/콘텐츠를 서로 다른 문구로 표시하며 NFT 앱 수집품·접수·확인 중·최종 발행을 혼동하지 않는다. 시연 화면은 실제 영업점·방문·혜택이 아니라는 한국어 설명을 잃지 않는다. 색만으로 상태를 전달하지 않는다.

## 검증과 완료 판정

1. 기존 모바일 전체 단위·typecheck·lint·Android JS export, 지갑 릴리스 표면, 사이트 허용 목록·접근성·privacy/bootstrap 검사를 통과한다.
2. 팔레트의 일반/보조 본문, 파란 텍스트·흰 버튼 글자, 성공/오류/상태면의 실제 light·dark 배경 조합을 자동 시험한다. 독립 `foundationColors`가 다른 색 값을 재도입하지 않는 회귀를 둔다. 반투명 글자는 **합성 후** 대비를 계산한다. 현재 `merchant-detail`의 DEMO 고지 `opacity: 0.78`은 새 파랑 위 약 4.44:1로 부족하므로 불투명하게 만들거나 계산상 4.5:1 이상으로 조정한다.
3. 실제 렌더링에서 Android 360/390/412dp 네 탭과 11개 화면의 주요 상태, 라이트/다크 전환·큰 글씨, 시연 웹 모바일/데스크톱·키보드 포커스를 확인한다. `@expo/ui Host`의 `seedColor`로 파생된 버튼 색도 실제 화면 대비를 확인한다. 웹의 다크 색상은 CSS 첫 선언만 읽는 기존 자동 검사에 의존하지 않고 dark media 계산값·스크린샷으로 확인한다. TalkBack·실제 기기·운영 release를 직접 실행하지 못했다면 `NOT_RUN`으로 남긴다.
4. `DESIGN.md`의 독립 foundation/잎색 제안은 과거 상태로 구분하고 이번 공통 팔레트 기준으로 갱신한다. README·TEST_STATUS·증거도 실제 코드·검사에 맞춘다. 화면 증거가 사용한 코드 커밋·기기·빌드 종류를 기록한다. 과거 PR #138 브라우저 시안 캡처를 수정된 운영 Android 실기로 주장하지 않는다.

## 제외·되돌리기
