# 모바일 탐색·방문·도감 UI 구조 설계

상태: 사용자 승인 · 2026-09-23 · Issue #126 · 상세 구현은 계획 검토 후 진행

## 목적과 범위

월계1동 지역 음식점 탐색·방문 인증·마스코트 수집 흐름을 Android 앱에서 이해하기 쉽게 만든다. 사용자는 ‘따뜻한 동네 음식 탐험 + 마스코트 수집’ 방향과 기본 이동을 `탐색 / 방문 인증 / 도감 / 내 정보`로 정리하는 B안을 승인했다. 이 문서는 그 방향의 구현 경계와 검증 조건을 구체화한다. API·DB, 보상·NFT·양도 정책, Google 인증·지갑 보안 모델은 바꾸지 않는다.

## 현재 근거와 문제

- `apps/mobile/src/app/_layout.tsx`는 모든 화면을 한 Stack에 등록한다. 기본 이동이 `apps/mobile/src/screens/merchant-list/index.tsx`의 여러 빠른 이동 버튼에 몰려 있다.
- `docs/evidence/android-merchant-list.png`에서는 큰 소개 문구가 실제 음식점 목록보다 많은 첫 화면 공간을 쓴다. `docs/evidence/android-collection.png`는 앱 수집품과 실제 NFT를 올바르게 구분하지만 카드의 시각 계층이 단조롭다.
- `apps/mobile/src/theme/palette.ts`에는 라이트·다크 의미색이 있고 대비 시험이 있다. 이를 버리지 않고 확장한다.
- 마스코트·음식점의 사용 승인된 이미지 자산이 저장소에 없으므로 신규 사진이나 소유 이미지처럼 보이는 그림을 만들지 않는다.
- **기존 충돌:** `docs/PRD.md`의 RQ-001은 로그인 없이 음식점 탐색을 `VERIFIED`로 표시하지만 `apps/mobile/src/app/_layout.tsx`는 비로그인 상태에서 라우트 전체를 인증 안내로 대체한다. 탭 UI 변경이 이 인증 모델을 해결했다고 주장하지 않는다. 인증 정책 변경은 별도 결정·시험이 필요하다.

## 접근법 비교와 선택

| 접근 | 이점 | 한계 |
| --- | --- | --- |
| A. 기존 Stack을 유지하고 제목·카드만 정리 | 변경과 회귀 위험이 작음 | 기본 이동 버튼이 첫 화면에 흩어진 문제는 남음 |
| **B. 기존 화면을 네 탭과 맥락 화면으로 재배치하고 스타일을 점진적으로 통일** | 사용자 흐름이 분명하고 기존 기능·경로를 재사용 | 라우팅·Android 뒤로 가기·딥링크 회귀 시험 필요 |
| C. 모든 화면·자산·모션을 한꺼번에 교체 | 표현 자유도가 큼 | 검증 범위와 미승인 자산·가짜 콘텐츠 위험이 큼 |

B안을 사용한다. 새 라이브러리나 데이터 모델 대신 기존 Expo Router·API hook·상태 표현을 재사용한다.

## 화면 구조와 경로

1. 루트 `AuthSessionProvider`와 계정별 `AppKitProvider`는 그대로 둔다. 로그인 상태에 따라 인증 안내 또는 앱 라우트를 보여주는 경계를 유지한다.
2. 기존 `index`, `claim`, `collection`, `settings`를 Expo Router의 `(tabs)` 그룹으로 옮긴다. [공식 Router 설명](https://docs.expo.dev/router/basics/core-concepts/)처럼 그룹명은 URL에 들어가지 않으므로 `/`, `/claim`, `/collection`, `/settings` 경로를 유지한다. [JS Tabs](https://docs.expo.dev/router/advanced/tabs/)를 사용하고 기존 Stack 안에 둔다. [SDK 57의 native tabs](https://docs.expo.dev/router/advanced/native-tabs/)는 `unstable` 경로이므로 이번 변경에서 채택하지 않는다.
3. `merchants/[merchantId]`, `recommendations`, `wallet`, `merchant`, `open`은 루트 Stack의 맥락 화면으로 유지한다. `/open` HTTPS 앱 링크와 `masscom` scheme을 변경하지 않는다.
4. 탭 전환·상세 화면 뒤로 가기·Android 시스템 뒤로 가기에서 예기치 않은 로그인/지갑 재생성이 없어야 한다. 계정이 바뀌면 기존의 `key={accountId}` 분리 경계를 유지한다.
5. 점주 기능은 일반 사용자용 기본 탭에 두지 않는다. 현행 권한 검사와 진입 경로를 확인해 `내 정보`의 보조 링크 등 한 곳에서 찾을 수 있게 하되, 점주 권한을 UI만으로 부여하지 않는다.

## 화면별 핵심 변경

- **탐색:** 짧은 화면 소개와 한 가지 추천/탐색 행동 뒤에 실제 음식점 목록을 배치한다. 목록·빈 상태가 첫 화면에서 시작되도록 소개 높이를 줄인다. 카드에는 실재 API가 주는 이름·이야기·주소·캠페인 상태·DEMO 여부만 쓴다. 사진·참여 성과를 만들어 넣지 않는다.
- **방문 인증:** QR/코드 입력, 확인, 수령 결과를 순서대로 읽을 수 있게 한다. 인증 실패·중복·만료·네트워크 오류 문구와 기존 멱등 동작을 유지한다. 지갑 연결을 요구하지 않는다.
- **도감:** 방문 수·앱 수집품·실제 NFT 수를 별도 레이블로 둔다. 수집품 카드와 발행 작업의 `접수 → 확인 중 → 최종 완료/실패` 상태를 구분한다. 지갑 연결은 실제 발행을 원할 때만 보이는 맥락 행동이다.
- **내 정보:** 운영 계정과 로그아웃·계정 전환을 먼저 보여주고, 개인정보·계정 삭제 설명과 파괴적 행동을 충분히 분리한다. 이미 발행된 NFT는 삭제되지 않는다는 안내를 유지한다.
- **추천·상세·지갑·점주:** 기존 기능을 유지하면서 새 탭에서 자연스럽게 진입·복귀할 수 있도록 링크와 제목만 필요한 범위에서 조정한다.

## 시각 언어와 컴포넌트

- `DESIGN.md`의 의미색을 기준으로 기존 청록 신뢰감을 보존하되 배경은 따뜻하게, 강조는 잎색 계열로 조정한다. 정확한 색상은 라이트·다크 대비 시험 후 결정한다.
- 큰 첫 화면 제목을 줄이고 한 화면의 주요 행동을 하나로 만든다. 반복되는 회색 카드와 빠른 이동 버튼은 줄인다.
- `theme`에 소수의 간격·글자·모서리 토큰을 두되, 현행 `colorsForScheme`와 각 화면의 `StyleSheet`를 한번에 갈아엎지 않는다. 반복되는 표현만 공통 컴포넌트로 묶는다.
- 새로운 마스코트 원본이나 음식점 사진은 이 작업의 필수 조건이 아니다. 권리와 자산이 확인될 때까지 숫자·경로 표식·텍스트로 수집 분위기를 만든다.

## 데이터·오류·보안 경계

- 기존 음식점·방문·도감 API hook을 변경하지 않는다. 서버 응답이 없으면 빈 화면을 꾸미지 않고 현재 로딩·오류·빈 상태를 명확히 보여준다.
- 실제 NFT 완료는 기존 체인 검증 결과에만 따른다. UI에서 접수나 앱 수집품을 발행 완료로 승격하지 않는다.
- 로그인·로그아웃·계정 전환, SecureStore, Reown 세션, 지갑 서명/요청 메서드, 점주 권한, 계정 삭제 동작은 변경하지 않는다.
- 실패 시 이전에 로드한 데이터를 유지하는 기존 동작과 재시도 가능 조건을 보존한다. 탭 전환만으로 같은 요청을 중복 제출하지 않는다.

## 접근성·실기 검증

- TalkBack에서 네 탭의 이름·선택 상태·버튼 역할·상태 메시지를 확인한다. 색상만으로 상태를 전달하지 않는다.
- 360/390/412dp 폭, 글꼴 확대 130%/200%, 라이트·다크, Android 하단 Safe Area에서 잘림과 겹침을 검사한다.
- 탭 경로, 상세·추천·지갑 진입과 뒤로 가기, `masscom://open`과 HTTPS `/open` 딥링크, 계정 전환 후 화면/지갑 상태 분리를 회귀 검증한다.
- 자동 검증: 모바일 관련 단위 시험, `typecheck`, `lint`, Android export, 기존 색 대비 시험. 실기 검증은 실제 연결 기기에서 수행한 항목만 PASS로 기록한다. OAuth D02 전체 수용 기준은 별개이며 UI 시험만으로 PASS로 바꾸지 않는다.

## 통합·되돌리기

- Issue #126의 한 브랜치와 한국어 PR 하나에서 설계·구현·시험·문서를 함께 검토한다. 설계 승인 전에는 UI 코드 변경을 시작하지 않는다.
- 라우트 그룹 도입 뒤 기존 경로·딥링크가 깨지면 먼저 회귀 원인을 수정한다. 되돌릴 때는 탭 그룹과 화면 이동 변경만 원복하고 API·DB·체인 상태는 건드리지 않는다.
- README·프로젝트 상태·테스트 상태는 실제 구현·검증 범위에 맞춰 같은 PR에서 갱신한다.
