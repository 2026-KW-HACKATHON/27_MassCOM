# 연합 미션·공유 마스코트 뽑기·재뽑기

2026-10-09 소유자 요청과 후속 결정이다. 소유자는 설계 보완과 구현을 위임했고 병렬 실행을 요청했다.

## 목표

실제 등록된 가게들이 함께 미션을 운영하고 손님이 서로 다른 가게를 방문하도록 한다. 기존 코스와 방문 원장, 그림 제작·도감·공간 꾸미기를 재사용한다. 운영 실적과 시연 가상 실적을 섞지 않는다.

## 연합 미션

- 2–4개 실제 등록 가게, 각 가게의 점주 동의 참조, 관리자 공개 검사. 동의가 없는 가게를 참여시킨 것으로 기록하지 않는다.
- 식사+카페 2곳, 골목 3곳, 동네 4곳 템플릿은 실제 가게 선택 양식을 돕는다. 샘플 점포를 운영 데이터로 만들지 않는다.
- 기간 내 인정된 방문으로 조각을 모아 완성 장면과 완주 기록을 얻는다. 코인 구매·뽑기·재뽑기는 방문으로 계산하지 않는다.
- 순서는 자유이며 첫 미완료 가게의 실제 상세 페이지로 안내한다. 기계용 sceneKey 대신 미션 제목을 보여 준다.
- 할인·실제 쿠폰은 기존 점주 동의·비용 상한 경계를 지킨다. 미션에서 재뽑기권을 무한 지급하지 않는다.

## 음식점 마스코트 뽑기권과 공유 풀

- 새 공유 풀의 초기 100개: 브론즈 50, 실버 35, 골드 14, 프리즘 1. 내부 PLATINUM 등급은 프리즘으로 표시한다.
- 고객별 독립 재고가 아니다. 브론즈 한 번이면 총 99, 브론즈 49. 다음 추첨 확률은 현재 남은 수량을 기준으로 한다.
- 프리즘 지급과 초기 100개 재충전, 회차 증가를 같은 DB 거래로 처리한다. 동시 고객과 재전송으로 차감·재충전을 중복하지 않는다.
- 같은 가게의 활성 신규 공유 풀은 하나다. 구 부분등급 풀은 존재하지 않는 상품을 만들지 않고 기존 약속·영수증을 보존하며 이행 범위를 표시한다.
- 미사용 음식점 권은 발급 후 최대 7일에 만료한다. 활성 보관함에서는 사라지고 기록은 남는다. 사용한 권으로 받은 코인은 만료시키지 않는다.
- 해당 가게의 유효 미사용 권을 가진 고객에게만 상세 확률·잔여 등급 수량·회차를 제공한다. 무권·마지막 권 사용·만료·계정 전환 시 캐시에서도 지운다.

## 재뽑기

- 코인 원본 1개와 재뽑기권 1장을 원자적으로 소비한다. 소유자는 등급 하락도 허용한다고 답했다.
- NORMAL/BRONZE는 전체, SILVER는 실버 이상, GOLD는 골드 이상. 같은 가게의 유효 풀을 사용한다.
- 결과를 미리 고르거나 프리즘을 보장하지 않는다. 사용 전 회수·차감·하락 가능성을 보여 주고, 결과에 이전/새 코인과 남은 권을 표시한다.
- NFT 요청 중/발행 완료 방문 코인을 회수하지 않는다. 서버 소유권·원장·멱등 복구와 이미지 권리를 유지한다.
- 보유 코인 상세는 공개 게시판의 고정 detail과 실제 보유 수량을 확인해 제공한다. 비공개 제작 초안은 제공하지 않는다.

## 일반 상자

- 새 일반 뽑기에서 COIN·CHARACTER를 제외한다. 이전 보유와 영수증은 보존한다.
- 재뽑기권·마일리지·가구·테마를 한 번에 하나 지급한다. 기존 가격은 브론즈100/실버200/골드400P다.
- 등급 가중치(1만): 브론즈 상자 8000/1700/280/20, 실버 상자 실버9400/골드550/프리즘50, 골드 상자 골드9900/프리즘100.
- 등급→종류→아이템 순으로 서버 암호학적 난수를 사용한다. 아이템 수가 달라도 등급 총확률이 임의로 달라지지 않는다.
- 재뽑기권 종류 가중치는 보상 희귀도에 따라 0.5–2%이고, 나머지는 기존 꾸미기 재화다. 공개 확률은 계산한 실제 항목별 값이다.
- 마일리지 기본량은 희귀도별20/40/80/160P로, 일반 상자의 지출이 무한 회수되는 구조를 만들지 않는다.

## 검증과 출시

동시 고객·프리즘 리필·7일 경계·확률 접근·재뽑기 하락/NFT 잠금·한 보상/멱등·방문 미션 부정 적립을 API/PG/앱에서 검증한다. 첨부 화면의 도감·권 확인·재뽑기 전후 레이아웃은 기존 앱 틀에서 비교한다. 새 API·웹·APK·시연 웹의 동의 버전은 함께 제공해야 한다. 실제 기기·공개 배포·유료 이미지 생성은 실행한 근거만 기록한다.

## 점주 체험 AI 생성 제한 후속 결정

- 계정이 가진 여러 점포에 합산해 KST 날짜별 시안 라운드 3회와 최종 생성 3회를 허용한다. 기존 완료 최종은 시안 잔여 횟수도 줄이지 않는다.
- 시안 네 장 요청도 하나의 라운드다. 시안/최종 생성 요청은 종류와 무관하게 앞선 성공 예약 후 60초가 지나야 한다.
- 계정 단위 advisory lock으로 날짜·쿨다운 검사와 비용 예약을 직렬화한다. 쿼터 조회 응답은 계정 잔여량과 재설정/쿨다운 시각을 포함하고, 차단 응답은 `Retry-After`를 제공한다.
- 점포별 원래 한도·월 예산·체험 점포의 역할 제한은 추가 한도와 동시에 유지한다. 이전 저장 행은 새 계정 한도에 소급 계산하지 않는다.
