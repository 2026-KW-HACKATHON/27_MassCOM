# 전체 고객 UI 실제 구현 요구사항

MassCOM에 첨부한 UI 시안과 기능 구성을 실제로 반영해줘.

저장소:
https://github.com/2026-KW-HACKATHON/27_MassCOM

가장 중요한 목표는 앱 전체의 디자인, 사용 경험, 기능 간 연결, 상호작용 디테일을 개선해서 실제로 사용하고 싶은 수준으로 완성도를 높이는 거야.

첨부 자료에는 최종 UI 이미지 23장과 그 안에 포함된 67개 화면 상태, 화면 목록, 원본 프롬프트, 수정 프롬프트, manifest, 갤러리 HTML이 있어. 현재 저장소와 진행 중인 변경을 먼저 확인하고, 이 자료를 기존 앱의 실제 기능과 데이터에 연결해서 구현해줘.

구체적인 구현 방법과 작업 순서는 네가 현재 코드를 확인한 뒤 자율적으로 판단해도 돼. 필요한 공통 컴포넌트 개편, 데이터 모델 변경, API 추가, 화면 구조 정리까지 포함해서 작업해줘.

## 1. 제품의 중심 방향

MassCOM의 핵심 흐름은 다음과 같아.

실제 지역 가게 탐색 → 방문 인증 → 가게 코인 수집 → 마이룸 전시와 꾸미기 → 친구·가게 이웃과 교류 → 새로운 가게 발견과 재방문.

마이룸, 친구, 놀이, 상점이 이 흐름 안에서 서로 이어지도록 만들어줘. 사용자가 각 기능을 이용하면서 무엇을 얻었는지, 다음에 무엇을 할 수 있는지 자연스럽게 이해할 수 있어야 해.

특히 다른 사람의 마이룸에서 전시 코인을 발견하고, 그 코인의 가게 정보와 획득 조건을 확인하거나 식사 초대로 이어지는 경험을 중요하게 봐줘.

## 2. 첨부 자료를 적용하는 기준

최종 PNG는 시각적 기준으로, 화면 목록과 프롬프트는 기능과 동작 의도를 이해하는 자료로 활용해줘.

원본 프롬프트와 수정 프롬프트가 충돌하는 부분은 해당 항목에 한해 최종 수정 내용을 우선해줘. 이미지 속 오기나 생성 오류도 수정 프롬프트의 내용을 기준으로 바로잡아줘.

특히 다음 구분을 유지해줘.

- 일반 뽑기권 사용은 기존 보유 코인을 유지하면서 새 코인을 얻는 동작이야.
- 새로 제안된 코인 리롤은 선택한 기존 코인을 회수하고 리롤권을 소모해 새 코인을 얻는 동작이야.
- NFT 발급 진행 중이거나 발급 완료된 대상은 리롤에서 제외해야 해.
- NFT 안내는 앱 안에서의 회수·리롤 제한을 정확하게 설명해줘.
- `06-store-neighbors` 보드의 활성 하단 탭은 최종 수정 기준으로 ‘탐색’이야.

이미지에 나온 사람, 가게, 보유량, 가격, 보상량, 재고, 방문 수는 예시야. 실제 화면은 서버 데이터와 확정된 정책을 사용하고, 새로운 보상 정책을 예시 숫자만 보고 확정하지 말아줘.

67개는 화면과 상태의 목록이므로, 실제 페이지·모달·바텀시트·컴포넌트 구성은 사용성과 현재 구조에 맞게 결정해도 돼.

## 3. 전체 구현 범위

첨부 시안 전체를 목표 범위로 잡고 다음 기능을 연결해줘.

### 홈과 공통 UI

마이룸과 동행을 중심으로 홈의 개성을 살리면서 보유 뽑기권, 방문 인증, 방문 목표, 친구와 우편 등 주요 행동을 쉽게 찾게 해줘.

하단 메뉴는 탐색·도감·홈·놀이·상점의 기능과 순서를 유지해줘. 하단 바 꾸미기는 테마·색상·아이콘 표현을 미리 보고 적용하는 기능으로 구현해줘.

프로필의 한 줄 소개를 포함해 공통 헤더와 상태 표시도 시안의 의도를 반영하되, 지도·카메라·게임처럼 본문 공간이 중요한 화면에서는 밀도와 크기를 적절히 조정해줘.

### 실제 가게 탐색과 방문

지도, 검색, 가게 상세, 길찾기, 방문 인증, 인증 완료와 보상 확인을 하나의 자연스러운 흐름으로 다듬어줘.

현재 코드에 있는 실제 지도, 가게 사진, 메뉴, 영업 상태, 입구와 위치 정보, 캠페인과 보상 조건을 확인하고 새 UI에서도 활용해줘. 인증은 기존 서버의 유효성 검사와 일회성 처리에 연결해야 해.

방문 결과에서 새 보상 확인, 도감, 마이룸 전시, 다음 목표까지 이어지게 해줘.

### 도감·뽑기·리롤·NFT

가게 → 코인 종류 → 브론즈·실버·골드·프리즘 4등급이라는 시안의 수집 구조를 반영해줘.

가게 전체 수집률과 특정 코인 종류의 등급 수집률을 구분하고, 미보유·보유·중복 수량·획득 경로·NFT 상태를 이해하기 쉽게 보여줘.

뽑기권 상세, 사용 확인, 획득 결과, 리롤 선택과 결과, 선택적 NFT 발급 흐름을 실제 소유 데이터와 연결해줘. 대표 설정과 마이룸 전시도 결과 화면에서 바로 이어져야 해.

### 마이룸·가구·보관함·상점

코인 전시, 동행과 의상 꾸미기, 자유로운 가구 배치, 벽과 바닥 편집, 구매한 물건의 보관과 배치를 구현 범위에 포함해줘.

상점에서 본 물건이 구매 결과, 보관함, 실제 마이룸에서도 같은 자산과 상태로 이어져야 해. 미리보기, 선택, 배치, 저장, 취소, 해제 등의 동작을 자연스럽게 만들어줘.

기존 캐릭터·의상·보유 수집품과 새 가구·테마 시스템이 함께 작동하도록 설계해줘.

### 친구·가게 이웃·교류

기존 친구 추가, 코드·QR, 우정 교환, 쪽지, 식사 초대를 새 화면에 연결해줘. 초대를 보낸 이후 상대방의 응답과 상태 변화도 확인할 수 있어야 해.

가게 이웃은 실제 방문이 확인된 공통 가게를 연결점으로 삼아 공개 마이룸을 방문하는 기능이야. 친구 추가 전에도 조건에 맞는 이웃의 방을 방문할 수 있고, 친구 추가는 별도 선택으로 제공해줘.

‘나만 / 친구 / 같은 가게 이웃’의 공개 범위, 방문자, 답방, 방명록과 반응, 숨기기·차단 등 필요한 동작을 일관되게 연결해줘. 공개 범위는 추천 목록뿐 아니라 실제 방 조회와 관련 API에서도 적용되어야 해.

공통 방문 가게와 공개된 방을 활용하고, 실제 가게 방문 시각이나 실시간 위치를 노출하지 않는 방향을 유지해줘.

### 놀이와 나머지 고객 화면

네 게임의 시각 표현, 조작감, 피드백, 결과와 보상 경험을 개선해줘.

현재 코드에서 실제 가게 메뉴·사진·포장·간판·보유 수집품을 놀이 콘텐츠로 연결하는 부분을 확인하고 적극적으로 활용해줘. 가게와의 연결이 플레이 중에도 알아볼 수 있게 드러나야 해. 실제 자료가 없는 경우에는 연습용 콘텐츠임을 구분해줘.

프로필, 탐험 여권, 우편과 미션, 설정, 로그인·동의·권한, 계정·외부 지갑·도움말·계정 삭제 흐름도 첨부 시안에 맞게 정리하고 기존 동작에 연결해줘.

## 4. 기존 코드와 반드시 대조할 부분

사전 검토에서 아래 차이가 확인됐으니 최신 코드에서 다시 확인해줘.

- 기존 방문 1·3·5회 보상 권리와 별도로 구매·지급되는 가게 뽑기권의 관계.
- 기존 상점의 캐릭터 재뽑기와 새로 제안된 ‘기존 가게 코인을 회수하는 리롤’의 차이.
- 기존 방 테마·전시 슬롯 구조와 새 자유 가구 배치·벽·바닥·보관함 구조의 차이.
- 기존 공개 랜덤 방 방문과 새 공통 방문 가게 기반 연결·공개 범위의 차이.
- 현재 코인 보유량 집계와 NFT 발급 권리 사이의 관계.
- 현재 게임의 실제 가게 콘텐츠 연결과 기존 보상·기록.

기존 코드를 재사용할 수 있는 부분은 활용하고, 새로운 기능에 필요한 데이터와 API는 함께 구현해줘. 구조를 바꾸더라도 기존 보유 코인, 보상 권리, 방문 기록, 친구 관계, 꾸미기와 게임 기록이 이어지도록 처리해줘.

## 5. 보상 규칙에서 결정이 필요한 부분

아래 항목은 시안만으로 확정하기 어려우므로 현재 정책과 구현을 확인하고, 중요한 선택이 필요한 부분만 쟁점·선택지·추천안으로 묶어서 확인해줘.

- 네 등급만 존재할 때 ‘일반 리롤권: 전체 등급’과 ‘브론즈 리롤권: 브론즈 이상’을 어떻게 구분할지.
- 방문 보상으로 뽑기권을 주는 것이 기존 보상에 추가되는지, 앞으로의 지급 방식을 바꾸는지.
- 리롤에서 같은 코인 재획득이나 등급 하락을 허용할지.
- 회수된 코인이 소멸하는지, 가게 풀로 돌아가는지.
- 실제 코인별 재고를 운영할지, 재입고와 확률을 어떻게 적용할지.
- 새 놀이·우정·방 방문 보상과 마일리지 사용처를 어떻게 맞출지.
- NFT 발급 실패·장기 대기 이후 리롤 가능 상태를 어떻게 판단할지.

기존 정책으로 처리할 수 있는 부분과 새 결정이 필요한 부분을 구분해줘. 결정이 필요한 항목과 독립적인 UI·기능·데이터 작업은 계속 진행해줘.

## 6. 퀄리티에서 중요하게 볼 기준

시안의 아이보리·민트·원목과 캐릭터·가구·금속 코인 표현을 바탕으로 일관된 디자인 체계를 만들어줘. 색상뿐 아니라 글자 크기, 여백, 카드, 버튼, 아이콘, 그림자, 선택 상태, 모션을 함께 정리해줘.

PNG는 디자인 참고로 활용하고, 버튼·텍스트·입력·선택·상태 변화는 실제 앱 컴포넌트로 구현해줘. 마스코트·가구·코인 등의 콘텐츠 자산은 각 화면에서 일관되게 재사용할 수 있게 구성해줘.

특히 다음 경험을 챙겨줘.

- 처음 가입해 방문·친구·코인·뽑기권이 없는 상태.
- 같은 가게의 공개 이웃이 없는 상태.
- 코드 만료, 재화 부족, 보상 소진, 조회·저장 실패.
- 구매·리롤·NFT 처리 중 앱을 닫았다 다시 연 상황.
- 편집 중 뒤로가기와 저장·취소.
- 게임 중 화면 이동과 복귀.
- 획득·구매·전시·우정 교환 이후의 명확한 피드백.

작은 Android 화면, 큰 글씨, 키보드, 안전 영역, 밝은·어두운 테마에서도 주요 행동에 접근할 수 있어야 해. 효과와 애니메이션은 반응성을 해치지 않도록 조절해줘.

## 7. 작업 방식과 완료 기준

구현 순서와 기술적인 방법은 자율적으로 정해줘. 핵심 사용 흐름부터 단계적으로 완성하고, 이어서 나머지 시안 범위를 구현해줘. 단계 구분은 전체 목표를 완성하기 위한 작업 순서로 사용해줘.

코드 구조, 컴포넌트 분리, 화면별 정보 배치, 적절한 인터랙션, 상태 처리 같은 세부 사항은 네가 판단해서 진행해도 돼. 중대한 미확정 보상·소유 규칙에 질문을 집중하고, 사소한 구현 결정마다 승인을 반복해서 요청할 필요는 없어.

저장소의 작업 지침과 기존 승인 범위를 따르고, 시연·운영 앱이 공유하는 기능은 공통 코드에서 개선해줘. 시연 데이터와 운영 데이터의 경계도 유지해줘.

계획 수립 후 실제 구현과 검증까지 진행해줘. 첨부 보드가 어떤 화면과 상태로 반영됐는지 추적할 수 있게 정리하고, 핵심 흐름은 실제 동작으로 확인해줘.

특히 다음 과정을 하나의 연결된 경험으로 검증해줘.

가게 탐색 → 방문 인증 → 보상 확인 → 코인 획득 → 도감 반영 → 마이룸 전시 → 이웃의 전시 확인 → 관련 가게 정보 확인.

완료 보고에는 실제 구현한 범위, 주요 디자인·동작 변경, 검증 결과, 변경 전후 화면, 아직 결정이나 추가 작업이 필요한 항목을 명확하게 정리해줘. 직접 확인하지 못한 실행 환경이나 동작은 구분해서 알려줘.
