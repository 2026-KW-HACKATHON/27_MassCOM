# 시연·운영 환경 분리와 읽기 전용 웹 도감 설계

상태: 부분 구현 · 2026-09-24 · [Issue #137](https://github.com/2026-KW-HACKATHON/27_MassCOM/issues/137). 정적 시연 웹·격리 로컬 seed·Android 세 variant 빌드 경계와 개발 DEMO 인증 package 제한은 병합됐고, 독립 로컬 시연 API·DB를 검증했다. 외부 API·웹 배포·실기 검증은 아직 아니다.

## 사용자 의도와 성공 기준

사용자는 가상 음식점 한 곳으로 제품 흐름을 선보이되, 시연용 앱·웹과 실제 운영 앱·웹을 구별하고 싶다. 웹은 음식점·도감을 **보는 용도**이며 QR 촬영, 방문 코드 수령, 지갑 연결·서명, NFT 발행 요청은 Android 앱에 남긴다. 시연 화면은 `DEMO` 배지만 붙이는 대신 실제 음식점·방문·보상이 아님을 짧은 한국어로 반복해 알려야 한다.

이 설계의 성공은 (1) 시연 데이터가 운영 점포 목록·계정·평가 실적에 섞이지 않고, (2) 누구나 시연 웹의 가상 도감을 읽되 운영 개인 도감은 본인만 읽고, (3) 웹에서 쓰기 동작이 불가능하며, (4) Android 시연 앱과 운영 앱을 한 기기에 나란히 설치해도 주소·세션·링크가 섞이지 않는 것으로 판정한다. 설계·자동 시험·기기 실기는 서로 다른 상태로 기록한다.

## 현재 기준선과 변경 이유

- 이 설계 작성 당시 `apps/mobile/app.config.ts`는 운영 `kr.masscom.wolgye`/`masscom`과 내부 개발 `kr.masscom.wolgye.dev`/`masscom-dev` 두 종류였다. 후속 빌드 경계 PR이 시연 `kr.masscom.wolgye.demo`/`masscom-demo` 설정을 추가하지만 실제 설치본·외부 API는 별도로 검증한다.
- `infra/lightsail/compose.yml`은 `api.masscom.kr`과 운영 PostgreSQL 한 벌이다. `ALLOW_INSECURE_DEMO_ACCOUNT=false`이며, 개발 계정 헤더를 인터넷에 열어 시연 계정으로 사용하지 않는다.
- `apps/api/src/postgres/merchant-catalog.ts`와 `recommendation.ts`는 활성·공개 캠페인인 `is_demo` 점포도 응답한다. 따라서 운영 DB에 가상 점포를 넣고 배지만 붙이는 방식은 운영 목록을 오염시킨다.
- `docs/index.html`은 정적 프로젝트 포털이다. `GET /merchants`는 공개 조회지만 `GET /collection`은 서버가 계정을 확인한다(`apps/api/src/server.ts`). 현재 정적 웹만으로 개인 도감을 안전하게 표시할 수 없다.
- Issue #136의 PR #138은 개발용 역할 선택 시안으로 병합됐고, 운영 네 탭·인증·점주 권한은 유지됐다. 이 명세는 그 미리보기 라우트를 시연 앱의 실제 기능 완료로 간주하지 않는다.

## 접근법 비교와 선택

| 접근 | 이점 | 한계 |
| --- | --- | --- |
| 운영 DB에 `is_demo=true` 한 행을 추가 | 현재 운영 APK에서 즉시 보임 | 공개 목록·추천에 가상 점포가 섞이고 방문/보상 처리도 운영 데이터와 결합됨. 채택하지 않음 |
| **공유 코드에 독립 시연 variant·정적 시연 웹·격리 API/DB를 둠** | 실제 기능을 재사용하면서 앱·웹·데이터의 경계를 검증 가능 | 별도 빌드·로그인·배포 설정과 교차 환경 시험 필요. 채택 |
| 모든 시연을 화면 녹화·고정 이미지로 대체 | 배포·인증 부담이 작음 | QR→도감 Android 흐름을 직접 검증할 수 없음. 발표 장애 대체 자료에만 사용 |

한 저장소에서 소스는 공유하되 환경을 `development`(로컬), `showcase`(가상 체험), `production`(실제 운영)으로 명시한다. 한 환경의 API URL·계정·DB·지갑/체인 키가 다른 환경으로 흘러가면 빌드 또는 서버 기동에서 거절한다. 새 유료 자원·DNS·공개 배포는 설계만으로 실행하지 않는다.

## 환경별 앱·웹·데이터 계약

| 항목 | 시연용 `showcase` | 실제 운영 `production` |
| --- | --- | --- |
| Android | 제안 package `kr.masscom.wolgye.demo`, scheme `masscom-demo`, 이름에 `체험용` 상시 표기. 초대된 시험자에게만 설치본 제공 | 기존 `kr.masscom.wolgye`, `masscom` 유지. 실제 방문·보상 정책만 사용 |
| 웹 주소 | 제안 `demo.masscom.kr`. 공개 가능한 고정 가상 점포·예시 도감의 읽기 전용 페이지 | 기존 `masscom.kr` 포털과 `/open`·법적 페이지 유지. 새 음식점 열람·로그인 후 본인 도감 페이지를 단계적으로 추가 |
| API·DB | 제안 `demo-api.masscom.kr`와 별도 PostgreSQL DB·계정 namespace. 공개 쓰기 API는 안전한 초대·인증이 준비되기 전 배포하지 않음 | 기존 `api.masscom.kr`와 운영 DB·계정. 가상 점포 seed를 넣지 않음 |
| 로그인 | 시연 웹의 **고정 예시 도감**은 로그인 없음. Android의 실제 QR 시연은 초대 시험 계정의 별도 인증·세션이 준비된 뒤 외부 공개 | 웹 개인 도감은 Google 로그인한 본인만 읽음. Android 기존 로그인과 지갑 상태는 유지 |
| NFT | 첫 시연에서는 앱 수집품까지만 다루고 실제 NFT 발행을 자동으로 시작하지 않음. 후속 시험망 발행은 별도 키·계약·Worker·증거가 있을 때만 `시험망 NFT`로 표시 | 앱에서 선택적으로 실제 발행을 요청하며, 체인 이벤트 검증 전에는 완료로 표시하지 않음 |

시연 웹의 고정 예시 도감은 실제 시연 Android 이용자의 계정 데이터와 자동 동기화되지 않는다. 공개 샘플을 모든 방문자가 함께 수정하면 다른 방문자의 시연 활동이 노출되고 내용이 매번 달라지기 때문이다. 시연 앱의 본인 진행 결과는 앱 안에서 확인한다. 운영 웹의 도감은 실제 계정별 `GET /collection` 결과만 사용한다.

## 웹 기능과 인증 경계

- 양쪽 웹에는 공개 음식점 탐색과 도감 열람만 둔다. 웹 소스·라우트·프록시의 허용 목록에 QR 스캔, claim issue/preview/redeem, 지갑 연결·서명, mint request를 넣지 않는다. 쓰기 API가 서버에서 계속 인증·권한 검사를 받는 것이 최종 방어선이다.
- 운영 웹의 개인 도감은 서버 측 웹 세션을 통해 `GET /collection`을 호출한다. 앱의 SecureStore 토큰이나 WalletConnect 세션을 브라우저로 복사하지 않는다. 브라우저에 장기 Bearer token을 `localStorage`로 저장하지 않는다. 웹 로그인 구현·세션 cookie·CSRF/로그아웃·캐시·동일 출처 경계는 별도 보안 리뷰와 통합 시험을 통과해야 한다.
- 운영 웹의 공개 점포 목록은 로그인 없이 읽을 수 있게 설계해 `RQ-001`의 앱 인증 게이트와 별도 상태로 판정한다. 개인 방문·도감은 검색엔진·공유 캐시·다른 계정에 노출하지 않는다.
- 현재 포털은 정적 HTML이므로 개인 도감은 정적 문서에 API 토큰을 삽입하는 방식으로 만들지 않는다. 정확한 웹 런타임·호스팅 요금·Google Web OAuth 조건은 구현 전에 공식 근거와 기존 자원 여유를 확인한다.

## 시연 데이터와 화면 문구

시연 DB에는 허락받지 않은 실제 음식점 명칭·사진·도로명 주소·주문번호를 복제하지 않는다. 가상 점포 한 곳, 공개 기간이 있는 시연 캠페인, 기존 첫/3/5회 고정 보상 목표를 별도 namespace로 준비한다. 시연 Android의 QR은 오직 해당 DB의 시험 계정에서만 발급·소비한다. 초기 웹 예시 도감은 개인 주소·거래 ID가 없는 고정 데이터로 제공한다. 생성·초기화 스크립트는 정확한 시연 DB를 확인하고 멱등 재실행·백업·되돌리기를 제공한다. 운영 DB에는 seed를 적용하지 않는다.

| 위치 | 사용자에게 보일 권장 문구 |
| --- | --- |
| 앱 첫 화면·웹 상단 고정 안내 | `체험용 가상 데이터로 서비스 흐름을 보여드립니다. 실제 영업점이나 방문 혜택과 연결되지 않습니다.` |
| 음식점 목록·상세 | `가상 점포 · 실제 방문할 수 없습니다` |
| QR·방문 결과 | `체험용 방문 코드입니다. 실제 주문·방문 인증이 아닙니다.` / `예시 방문 기록` |
| 도감 카드 | `앱 안의 예시 수집품 · 실제 NFT가 아닙니다` |
| NFT 표시가 필요한 경우 | 미발행은 `NFT 발행 전`; 실제 별도 시험망 거래가 최종 검증된 경우에만 `Base Sepolia 시험망 NFT` |
| 웹 바닥 안내 | `이 페이지의 점포·방문·수집품은 기능 설명을 위한 가상 예시이며 실제 운영 성과가 아닙니다.` |

`DEMO` 배지는 보조 표식으로만 사용한다. 의미는 본문 텍스트와 화면 읽기 접근성 이름에도 포함한다. 실제 NFT가 없는 시연 도감에는 가짜 `FINALIZED`, 임의 거래 해시, 가상 매출·참여 점포 수를 만들지 않는다. 운영 화면에는 시연 고정 문구가 유출되지 않는다.

## 분리 실패·오류 처리와 검증

- 앱 빌드: package·scheme·앱 이름·API URL·OAuth audience·Reown project ID·App Links host를 환경별로 검증한다. 시연 빌드가 운영 API를, 운영 빌드가 시연 API/DEMO 변수에 연결되면 실패시킨다.
- 서버·DB: 시연/운영 DB URL·인증 비밀·HMAC·Worker/체인 키를 분리한다. 운영 `ALLOW_INSECURE_DEMO_ACCOUNT=false`를 유지한다. 외부 시연 API는 헤더만 넣은 익명 계정 접근을 허용하지 않는다.
- 도감: 계정 A/B 응답과 시연/운영 데이터를 교차 조회해 다른 사람·환경의 방문·주소·수집품이 0건인지 확인한다. 웹 오류와 빈 도감은 다른 문구로 표시한다.
- 웹: 공개 시연 고정 데이터에 개인 정보가 없고, 운영 도감 응답이 로그인 전·로그아웃 후·공유 캐시에서 보이지 않으며, QR·방문·발행 쓰기 경로가 없음을 시험한다.
- 실기: Android 시연·운영 앱 동시 설치와 각 scheme/App Link 복귀, 외부 HTTPS 두 환경, 360/390/412dp·큰 글씨·접근성, 실제 연결 기기의 결과를 각각 기록한다. 자동 테스트·로컬 서버 결과로 외부 시연 완료를 주장하지 않는다.

## 단계·통합·되돌리기

1. 이 명세와 구현 계획을 검토한다. 현재 운영 API·DB·포털·APK는 변경하지 않는다.
2. 먼저 고정 가상 도감의 읽기 전용 시연 웹과 환경 교차 연결을 거절하는 빌드/서버 경계를 구현·시험한다. 외부 배포 전 도메인·요금·권한을 확인한다.
3. 별도 시연 앱/API/DB에 가상 점포 한 곳과 초대 시험 계정을 연결하고 Android QR→앱 도감까지 실증한다. 운영 점포 데이터에는 접근하지 않는다.
4. 운영 웹에 공개 점포 열람과 안전한 개인 도감 로그인·읽기 기능을 추가한다. 웹 세션 보안과 계정 삭제 정책을 별도 리뷰한다.
5. 실제 구현은 Issue #137에 연결한 소수의 기능별 한국어 PR로 검토하고 CI·필수 리뷰를 우회하지 않는다. Issue #136의 미병합 UI와 충돌하면 해당 변경을 먼저 확인해 조정한다.

문제가 생기면 시연 배포·별도 DB만 중지하고 기존 `masscom.kr`·`api.masscom.kr`·운영 Android 설치본에는 영향을 주지 않게 한다. 시연 데이터 정리는 정확한 DB·namespace와 백업을 확인한 뒤 별도 명령으로 수행한다. Google Play 배포·메인넷·대회 최종 제출·저장소 공개는 이 설계의 자동 실행 범위 밖이다.
