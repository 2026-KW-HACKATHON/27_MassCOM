MassCOM 실사용 전환 및 현실 연결·앱·디자인 전면 고도화 요청
프로젝트: https://github.com/2026-KW-HACKATHON/27_MassCOM
MassCOM의 최신 코드와 현재 사용자 흐름을 확인하고, 실제 지역 가게에서 사용할 수 있는 서비스로 발전시키기 위한 큰 개편을 진행해줘.
이번 작업의 핵심은 실제 지도와 실제 가게 정보를 기반으로 탐색·방문·수집·보상·재방문이 자연스럽게 이어지는 경험을 완성하는 것이야. 동시에 앱의 구성, 시각적 디테일, 조작감, 수집품과 캐릭터의 표현, 점주 운영 경험까지 함께 높은 수준으로 다듬어줘.
단순한 지도 화면 추가나 색상·여백 수정 정도로 범위를 제한하지 않았으면 해. 필요한 경우 화면 구조, 데이터 모델, API, 추천과 목표 시스템, 가게 등록·정보 관리, 현장 방문 흐름까지 함께 수정해도 돼.
구체적인 지도 제공자, 구현 기술, 데이터 설계, 화면 구성, 작업 순서와 검증 방법은 네 판단에 맡길게. 아래 내용은 달성할 목표와 검토 방향이며, 더 적합한 해결책이 있으면 조정해도 돼.
다만 실제 지도, 현실의 가게 탐색과 방문 흐름, 수집·게임과 현실의 연결, 앱·디자인 품질 향상이라는 핵심 범위를 임의로 축소하거나 첫 단계만 구현한 뒤 나머지를 후속 제안으로 남기지는 말아줘.
1. 이번 개편에서 만들고 싶은 서비스 경험
MassCOM은 사용자가 지역 가게를 발견하고 방문한 경험을, 갖고 싶은 코인과 수집품·동행·배지·꾸미기로 남기는 서비스야.
다음과 같은 흐름이 실제로 자연스럽게 이어졌으면 해.
사용자가 앱을 열고 지금 갈 만한 가게를 찾는다. 실제 지도에서 위치와 이동 방법을 확인하고, 가게의 메뉴·가격·영업 상태·방문 조건·얻을 수 있는 수집품을 이해한다. 도착하면 가게를 찾고 직원에게 방문을 확인받는 과정이 어렵지 않다. 수집품과 보상을 정확하게 받고, 감상하거나 아바타와 공간에 활용한다. 이후 원하는 수집품이나 친구의 전시를 보고 다른 가게를 방문하거나 좋아했던 가게에 다시 가고 싶어진다.
방문하지 않는 날에도 게임·도감·꾸미기를 즐길 수 있지만, 그 경험이 내가 발견한 가게와 모은 물건을 떠올리게 했으면 해.
점주도 참여 준비부터 가게 정보 수정, 방문 확인, 쿠폰 처리, 캠페인 관리, 직원 관리와 효과 확인까지 실제 업무에서 부담 없이 사용할 수 있어야 해.
이번 개편의 판단 기준은 기능의 수보다 이 전체 흐름이 현실에서 얼마나 자연스럽고 믿을 만하며 매력적으로 작동하는가야.
2. 최신 구현을 확인하고 이미 개선된 부분은 활용해줘
이전 검토 기준은 main b69ebc621a3dc6f237829d46cc2b4de3105b8ca8이지만, 실제 작업은 현재 최신 상태에서 시작해줘.
최근에는 요약 홈과 목적별 상세 화면의 분리, 게임 규칙 개선, 캐릭터 착용 원화와 장비 아트, 테마 팩, 배지와 꾸미기 해금, 친구·우편, 이미지·영상 공유, 점주 운영 기능 등이 추가되거나 개선됐어.
따라서 오래된 평가를 그대로 적용해서 이미 해결한 문제를 다시 만드는 작업으로 시작하지 말아줘. 코드와 실제 실행을 확인하고, 현재 부족한 부분과 앞으로 필요한 구조를 구분해줘.
특히 홈을 짧게 정리한 최근 방향은 고려해줘. 새 기능을 추가하면서 다시 긴 목록과 안내를 홈에 모두 쌓아 스크롤 부담을 키우지 않았으면 해.
반면 기존 그림 지도는 실제 위치를 나타내는 방식이 아니었고, 길찾기는 주소 검색으로 연결했으며, 가게의 영업시간도 자유 입력 문자열 중심이었어. 최신 상태에서도 그렇다면 이번 작업에서 실사용 기반으로 바꿔줘.
코드 구현, 로컬 실행, 실제 기기 확인, 공개 배포 상태는 구분해줘. 서로 다른 빌드나 서버를 보고 검증 완료로 판단하지 말아줘.
3. 앱 안에서 사용할 수 있는 실제 지도를 도입해줘
실제 지형과 도로, 가게 좌표를 표시하는 지도를 앱의 가게 탐색에 도입해줘.
외부 지도 앱을 여는 버튼이나 정적인 지도 이미지로 이번 요구를 충족했다고 보지는 말아줘. 앱 안에서 지도를 움직이고 확대·축소하며 가게를 선택하고 탐색할 수 있어야 해.
네이버 Maps, 카카오 지도 등 적합한 제공자를 최신 공식 문서와 현재 프로젝트의 호환성, 비용, 데이터 이용 조건을 기준으로 검토하고 선택해줘. 여러 제공자를 불필요하게 동시에 도입할 필요는 없어.
지도 표시와 장소 검색, 주소 변환, 보행 경로 계산이 각각 어디에서 제공되는지 확인해줘. 서로 다른 제공자의 데이터를 함께 사용하는 경우에는 표시·보관·출처·이용 조건까지 확인해서 설계해줘.
현재 앱 구조에 맞는 네이티브 SDK, 연동 모듈, 웹 지도 등의 방식을 선택해도 돼. 단순히 구현하기 쉽다는 이유로 조작감이나 접근성, 성능이 떨어지는 방식을 최종안으로 삼지 않았으면 해.
실제 지도에서는 다음 경험을 함께 검토해줘.
- 현재 위치 확인과 사용자가 직접 지정한 기준 위치.
- 화면에 보이는 지역 안에서 가게 찾기와 검색 결과 갱신.
- 지도와 목록에서 같은 가게·선택·필터 유지.
- 가까운 마커의 묶음 처리와 같은 건물 안 여러 가게의 선택.
- 선택한 가게를 가리지 않는 상세 패널과 지도 이동.
- 상세 화면이나 외부 길찾기에서 돌아왔을 때 탐색 상태 복원.
지도 위 가게 위치를 그림의 고정 좌표나 ID 해시로 정하지 말아줘. 가게 수가 늘어도 지도에서 표시 가능한 수를 임의로 작은 숫자로 제한하지 말고, 현재 화면 범위와 확대 수준에 맞게 처리해줘.
기존 그림 지도는 서비스의 분위기를 살리는 탐험 장면이나 전시 공간으로 재활용할 수 있어. 다만 실제 길찾기용 지도와 혼동되지 않게 역할을 구분해줘.
4. 실제 가게 위치와 데이터의 신뢰성을 만들어줘
실제 지도에 필요한 가게 위치 데이터와 관리 흐름을 함께 구현해줘.
주소를 좌표로 변환하는 것뿐 아니라, 같은 이름의 다른 지점이나 같은 건물의 다른 점포가 잘못 연결되지 않도록 해줘. 외부 장소 ID를 활용하더라도 MassCOM의 가게 식별자와 관리 권한은 별도로 유지해줘.
가게 위치에는 필요에 따라 건물 위치와 실제 출입구를 구분할 수 있게 해줘. 층·호수·출입구 설명·점주가 확인한 핀 위치 등이 현실에서 가게를 찾는 데 도움이 되도록 설계해줘.
기존 가게의 좌표를 채울 때는 확인 가능한 변환 결과를 사용하고, 모호한 결과는 점주나 운영자가 확인할 수 있도록 해줘. 변환 실패나 미확인 좌표를 임의의 위치로 대체해 실제 위치처럼 표시하지 말아줘.
좌표계와 위도·경도 순서를 일관되게 처리하고, 잘못된 범위나 뒤바뀐 값도 검증해줘.
외부 지도에 등록된 실제 장소와 MassCOM 참여 가게는 구분해줘. 외부 검색 결과에 나온다는 이유만으로 보상을 제공하는 가게로 자동 등록하거나 참여 중이라고 표시하지 말아줘.
가게의 실재 여부, 관리 권한 확인, 캠페인 준비와 게시 가능 상태가 연결되도록 점주 등록·참여 준비 흐름도 검토해줘. 실제 제휴나 점주 동의가 필요한 부분은 코드나 가상 데이터로 대신 완료 처리하지 말아줘.
운영용 실제 가게 정보, 시연용 가상 점포, 개발·검증용 데이터의 경계는 유지해줘.
5. 가게 상세에 현실에서 필요한 정보를 갖춰줘
가게 상세는 수집품 설명뿐 아니라 실제 방문을 결정하고 준비하는 화면이어야 해.
현재 정보와 점주 입력 부담을 고려해, 필요한 항목과 배치를 직접 설계해줘. 대표 메뉴와 가격, 가게 분위기, 위치와 입구, 영업시간, 이용 방식, 방문 인정 조건, 캠페인과 보상 등을 사용자가 이해할 수 있어야 해.
현실 정보를 무조건 많이 나열하기보다는 방문을 결정하는 데 필요한 정보와 도착 후 필요한 정보를 구분해서 보여줘.
특히 다음 상황을 처리할 수 있는 기반을 만들어줘.
영업시간과 예외
요일별 영업시간, 휴게시간, 마지막 주문, 날짜를 넘기는 영업, 정기 휴무와 임시 휴무 등을 적절히 표현해줘. 가게 시간대와 날짜 경계도 일관되게 처리해줘.
기존 자유 입력 영업시간은 보존하면서 필요한 구조로 옮길 수 있게 해줘. 모호한 문장을 자동 해석한 결과를 검증 없이 확정 정보로 사용하지 말아줘.
등록된 시간표로 계산한 상태와 점주가 직접 알린 임시 상태를 구분하고, 자료가 부족하면 확인 필요처럼 정직하게 보여줘. 실제로 확인하지 않은 영업 상태를 실시간 확인한 것처럼 표시하지 말아줘.
가게의 현재 상태
가게 영업 여부, 캠페인 참여 가능 여부, 방문 보상 발급 가능 여부, 쿠폰 사용 가능 여부를 서로 혼동하지 않게 해줘.
휴무·캠페인 종료·일시 중지·혜택 소진 등의 상황에서 기존 수집품과 이미 발급한 쿠폰이 어떻게 보이는지도 함께 확인해줘.
사진과 방문 안내
점주가 제공한 실제 가게·메뉴·출입구 사진과 AI로 만든 마스코트·수집품 이미지를 구분해줘. 생성 이미지를 실제 매장 사진처럼 쓰지 말아줘.
정보의 출처와 최근 확인·수정 상태를 필요한 범위에서 관리하고, 잘못된 위치나 영업시간을 바로잡을 수 있는 흐름도 마련해줘. 사용자 제보가 확인 없이 공식 정보로 바뀌지 않도록 해줘.
6. 실제 이동과 방문 선택에 도움이 되는 탐색을 만들어줘
검색·지도·목록·추천·찜한 수집품이 같은 방문 선택을 도와야 해.
사용자가 원하는 상황에 맞춰 가까운 가게, 아직 가보지 않은 곳, 현재 참여 가능한 캠페인, 원하는 보상을 얻을 수 있는 곳 등을 고를 수 있도록 해줘.
거리 정보는 무엇을 기준으로 계산했는지 명확해야 해. 지도 중심과의 거리인지 현재 위치와의 거리인지 구분하고, 직선거리를 도보 이동거리처럼 표시하지 말아줘.
보행 경로와 예상 이동시간을 제공할 때는 실제 지원되는 경로 API와 결과를 사용해줘. 자동차 경로를 보행 경로로 표시하거나, 두 점 사이에 선을 그린 것을 실제 길처럼 보여주지 말아줘.
앱 안의 경로 확인과 네이버 지도·카카오맵 같은 외부 길찾기 연결을 적절히 함께 제공해도 돼. 외부 연결은 가능한 경우 정확한 점포·좌표·이동 방식으로 이어지게 하고, 앱이 없을 때의 대안도 처리해줘.
여러 가게를 둘러보는 짧은 탐험 코스도 이번 범위에서 검토하고 구현해줘. 실제 가게 위치, 이동 경로, 영업시간, 사용자의 관심과 수집 진행을 활용해 현실적으로 가능한 동선이었으면 해.
이동시간과 가게에서 머무는 시간은 구분하고, 경로 탐색 실패나 휴무·캠페인 변경 시 다른 가게 선택이나 코스 수정이 가능해야 해. 확인할 수 없는 대기시간이나 접근성을 임의로 보장하지 말아줘.
현재 위치가 없어도 기준 지역이나 출발지를 직접 정해서 사용할 수 있도록 해줘.
7. 가게에 도착한 뒤의 방문 인증과 쿠폰 사용을 다듬어줘
실제 매장에서 사용자가 무엇을 해야 하는지, 직원이 무엇을 확인해야 하는지 명확하게 만들어줘.
도착 전에는 방문 인정 조건을 이해할 수 있어야 하고, 도착 후에는 QR이나 코드, 직원 확인과 보상 수령의 순서를 쉽게 찾을 수 있어야 해.
기존 방문 인증의 정확성과 서버의 중복 방지 구조는 유지해줘. 현재 위치와 근처 도착은 안내를 위한 정보로 활용하되, GPS 근접만으로 방문을 확정하거나 보상을 자동 지급하지 말아줘.
현장에서 발생할 수 있는 다음 상황을 고려해줘.
코드를 잘못 입력하거나 유효기간이 지난 경우, 직원이 다른 손님의 코드를 확인한 경우, 확인 도중 인터넷이 끊긴 경우, 여러 번 눌렀지만 처리 결과를 받지 못한 경우, 앱을 닫았다가 다시 열었을 때 이미 지급된 보상을 복구해야 하는 경우야.
처리 중·확인 필요·실패·완료를 구분하고, 응답을 받지 못했다고 중복 차감이나 중복 지급이 발생하지 않도록 해줘. 오프라인에서 확인하지 못한 거래를 성공처럼 표시하지 말아줘.
쿠폰은 사용할 수 있는 가게, 기간, 조건, 사용 방법을 보여줘. 사용 전 확인과 사용 완료 결과가 사용자·직원 화면에서 일관되어야 하고, 캡처나 오래된 화면만으로 사용 여부를 판단하지 않도록 기존 검증을 활용해줘.
방문이나 쿠폰 처리가 취소·수정됐을 때는 이력과 영향을 이해할 수 있어야 해.
8. 수집·미션·게임을 실제 가게와 더 깊게 연결해줘
최근 개선한 네 게임과 수집·꾸미기 구조를 활용하면서 현실의 가게와 연결되는 내용을 강화해줘.
내가 방문하거나 관심을 가진 가게의 상품·메뉴·포장·간판·수집품이 게임과 탐험 목표에 의미 있게 나타났으면 해.
다만 가게 이름과 배경만 바꾸는 것으로 끝내지 말고, 조작하는 물건과 상황, 완성한 결과, 얻는 꾸미기에도 연결이 느껴지게 해줘.
현재 개선된 쌓기·짝 찾기·배달·주문 게임의 규칙을 다시 확인해줘. 좋은 부분은 유지하고, 실제 가게와의 관계나 플레이 품질이 부족한 부분을 네 게임 모두에서 보완해줘.
보유 수집품이 없는 사용자에게는 완성도 있는 연습 경험을 제공하고, 방문과 수집으로 새로운 장면과 표현이 넓어지게 해줘. 점주가 게임을 직접 제작해야 하는 구조는 피했으면 해.
실제 방문으로 얻는 코인과 방문 이력, 게임 성취로 얻는 장식과 배지는 역할을 구분해줘. 게임 결과가 실제 매장 방문이나 구매처럼 기록되지는 않아야 해.
지도와 연결된 탐험에서도 이동 중 빠른 터치나 화면 집중을 요구하는 게임을 진행시키지 말아줘. 가게를 찾고 이동하는 과정과 멈춰서 플레이하는 과정의 사용 맥락을 구분해줘.
미션은 실제 참여 중인 가게와 달성 가능한 조건을 바탕으로 제공해줘. 원하는 수집품, 다른 가게 발견, 좋아하는 가게의 재방문이 균형 있게 목표로 이어졌으면 해.
친구의 가게 추천이나 식사 초대도 실제 위치·시간·가게 상태를 확인하는 흐름과 연결해줘. 친구 간 약속을 실제 매장의 예약이 완료된 것처럼 표현하지 말아줘.
9. 앱 구조를 현실에서 쓰기 편하게 크게 정리해줘
최근 홈 요약과 상세 분리의 취지는 유지하되, 실제 탐색과 방문에 맞춰 전체 정보 구조를 검토해줘.
사용자가 상황에 따라 필요한 행동을 쉽게 찾을 수 있어야 해.
처음 들어와 가게를 고르는 상황, 길을 찾는 상황, 매장 앞에서 방문 인증을 하는 상황, 쿠폰을 제시하는 상황, 집에서 수집품과 아바타를 감상하는 상황은 중요하게 보여줄 정보가 서로 달라.
이 맥락에 맞게 홈·검색·지도·가게 상세·방문·보관함·전시의 역할과 이동 흐름을 정리해줘.
같은 가게를 여러 화면에서 다시 찾아야 하거나, 목표로 저장한 수집품의 획득 방법을 다시 검색해야 하거나, 외부 지도에서 돌아오면 처음부터 탐색해야 하는 불편이 없었으면 해.
앱 링크나 알림으로 특정 가게·쿠폰·보상에 들어왔을 때에도 필요한 인증을 거친 뒤 원래 목적지로 이어지게 해줘.
메뉴와 버튼을 계속 추가하기보다 중복된 역할을 통합하고, 상세 정보는 필요한 순간에 펼쳐 볼 수 있도록 해줘. 구체적인 탭 구성과 화면 배치는 최신 사용자 결정과 실제 흐름을 확인해서 판단해줘.
10. 현실 정보와 수집 경험이 어울리는 디자인을 완성해줘
실제 지도와 가게 사진을 도입하더라도 MassCOM의 따뜻한 동행·수집 분위기는 유지해줘.
대신 모든 화면을 같은 정도로 화려하게 꾸미지는 않았으면 해.
지도·영업시간·방문 인증·쿠폰 처리에서는 정보의 가독성과 조작의 명확성이 우선이고, 팩·코인·배지·아바타·전시에서는 물건의 매력과 감상 경험에 더 큰 비중을 줘.
이 두 영역이 글자, 아이콘, 패널, 색, 그림자와 전환에서 하나의 서비스처럼 이어져야 해.
지도와 가게 선택
마커는 선택·미방문·방문·수집 완료 등의 상태를 알아보기 쉽게 표현하되, 여러 의미를 작은 아이콘 하나에 과도하게 넣지 말아줘. 세부 정보는 선택한 가게의 패널에서 보여줘.
지도 조작과 상세 패널 조작이 충돌하지 않고, 마커와 경로·현재 위치·필수 지도 표기가 가려지지 않아야 해.
가게 사진과 대표 수집품은 각각의 역할을 살려 보여줘. 실제 장소에 대한 신뢰와 수집품에 대한 기대가 함께 생기면 좋겠어.
아바타·배지·코인
최근 만든 착용 원화와 아트 자산을 활용하고, 캐릭터별 조합의 자연스러움과 동작을 더 다듬어줘. 장비의 앞뒤 관계, 손과 물건의 접촉, 포즈의 의미, 작은 화면에서의 식별성을 확인해줘.
코인의 두께·모서리·문양·금속과 색칠된 면·기울임 반사를 실제로 감상하고 싶은 수준으로 개선해줘. 강한 반짝임 때문에 원화와 글자가 보이지 않는 문제도 피해야 해.
미리보기, 획득, 장착, 전시와 공유에서 같은 물건이 같은 모습으로 이어져야 해.
화면의 세부 완성도
제목의 줄바꿈, 숫자와 단위, 긴 가게 이름과 주소, 가격 범위, 날짜와 시간, 남은 조건을 읽기 좋게 정리해줘.
로딩 중 레이아웃이 크게 흔들리거나, 이미지가 뒤늦게 나타나 버튼 위치가 바뀌거나, 주요 행동이 하단 패널·키보드에 가려지는 문제를 확인해줘.
선택·눌림·저장 중·완료·실패의 반응도 각 화면에서 일관되어야 해. 필요한 화면에서는 햇빛 아래 가독성, 한 손 조작, 큰 글자와 스크린리더도 고려해줘.
11. 소리·진동·전환과 실제 기기 품질을 마무리해줘
소리와 진동은 코드에서 호출했다는 것만으로 완료 처리하지 말아줘.
최근 실기 기록에 복구된 부분과 아직 미확인·실패로 남은 부분이 있으니 최신 기록을 확인하고, 가능한 실제 기기에서 사용자가 체감하는 결과를 검증해줘.
지도 이동과 필터 선택, 방문 확인, 팩 개봉, 코인 획득, 게임 성공과 실수, 기록 경신이 각각 어떤 반응을 줘야 하는지 정리해줘.
반복 조작마다 과한 진동이나 효과음을 주지 말고, 사용자의 소리·진동·모션 설정을 존중해줘. 소리 없이도 중요한 상태를 알 수 있어야 해.
위치 갱신·지도 렌더링·수집품 반사·캐릭터 동작을 함께 사용할 때의 성능과 배터리 부담도 확인해줘. 보이지 않는 화면에서 센서와 애니메이션이 불필요하게 계속 실행되지 않도록 해줘.
성능 목표는 현재 기기와 변경 범위에 맞게 정하고, 실제 측정 결과와 확인하지 못한 부분을 구분해줘.
12. 점주가 실제 가게 정보를 관리하고 서비스를 운영할 수 있게 해줘
실제 지도 도입과 함께 점주 참여 준비도 끝까지 연결해줘.
가게 등록 후 위치와 출입구를 확인하고, 영업시간과 메뉴를 입력하고, 방문 조건과 수집품을 준비한 뒤, 실제 고객 화면에서 어떻게 보이는지 확인하고 게시하는 과정이 이해하기 쉬워야 해.
기존 체크리스트는 단순한 완료 표시를 넘어, 잘못된 위치·누락된 필수 조건·유효하지 않은 기간 등을 수정하는 작업으로 이어지게 해줘.
일상 운영에서는 임시 휴무, 오늘의 변경 사항, 메뉴와 가격 수정, 캠페인 상태 확인 등을 적은 조작으로 처리할 수 있도록 해줘. 점주가 수정한 정보가 검색·지도·상세·추천·알림에 일관되게 반영되어야 해.
이미 구현한 캠페인 직접 연장, 직원 권한 관리, 방문 확인과 쿠폰 처리, CSV 내보내기, 알림 기능은 유지하면서 사용성과 연결을 보완해줘.
여러 직원이 동시에 작업하거나, 직원 권한이 변경되거나, 가게 정보가 갱신되는 상황에서도 잘못된 처리와 오래된 안내가 남지 않도록 해줘.
운영자는 실제 참여 준비가 완료되지 않은 가게를 구분하고, 위치·정보 오류나 중단된 캠페인을 바로잡을 수 있어야 해. 대규모 별도 관리 시스템을 만드는 것보다는 실제 운영에 필요한 작업을 기존 화면에 연결해줘.
13. 지도·위치·데이터 연동을 실제 운영 가능한 방식으로 구현해줘
이번 요청에는 실제 지도 SDK/API 도입, 필요한 일반 의존성 추가, 가게 위치 데이터와 검색 구조 보완, 선택적인 현재 위치 이용 흐름을 포함해.
과거 그림 지도 구현 당시의 “현재 위치를 사용하지 않는다”는 선택만을 이유로 이번 실제 지도 기능을 보류하지 말아줘.
현재 위치는 필요한 기능을 사용할 때 이유를 설명하고 요청해줘. 기본적으로 앱 사용 중 필요한 범위를 우선하고, 지속적인 백그라운드 추적이나 이동 경로 저장은 이번 목적을 위해 자동으로 추가하지 말아줘.
위치 권한 거부, 대략적인 위치, 위치 서비스 꺼짐, 오래된 위치, 정확도가 낮은 위치를 구분해서 처리해줘. 권한이 없어도 지역이나 출발지를 직접 선택해 탐색할 수 있어야 해.
친구·점주에게 사용자의 실시간 위치나 이동 경로를 자동 공개하지 말아줘. 위치를 로그·통계·외부 공유에 남기는 범위도 최소화하고, 필요한 개인정보 안내와 관련 정책을 최신 공식 근거로 확인해줘.
지도·장소·경로 요청은 사용량과 비용을 고려해 설계해줘. 지도 이동 중 불필요한 반복 요청, 오래된 응답이 최신 선택을 덮어쓰는 문제, 과도한 전체 목록 조회를 피하고, 필요한 범위 검색·요청 제어·묶음 처리·캐시를 적용해줘.
캐시와 지도 이미지·장소 데이터의 보관은 제공자의 이용 조건 안에서 처리해줘. 서비스 제공자 표기나 로고를 가리지 말고, 지도 화면을 공유 이미지로 내보내는 기능도 이용 조건을 확인해줘.
클라이언트에서 쓰도록 설계된 SDK 식별자와 서버 전용 비밀키를 구분하고, 패키지·서명·도메인 등 적용 가능한 제한을 설정해줘. 운영·시연·개발 환경도 구분해줘.
외부 지도 API 장애나 사용 한도 초과 시 앱 전체가 사용 불가능해지지 않도록 가게 목록·주소·문의·외부 지도 연결 등의 대안을 제공해줘. 실패한 실제 지도 대신 가상 지도를 조용히 보여주고 정상인 것처럼 처리하지 말아줘.
14. 현실에서 효과를 판단할 수 있는 기록을 마련해줘
실제 가게 탐색과 방문 흐름을 개선할 수 있도록 필요한 지표를 현재 데이터와 연결해줘.
지도에서 가게를 선택한 것, 가게 상세를 본 것, 길찾기를 연 것, 방문 목표로 저장한 것, 방문을 확인받은 것, 쿠폰을 사용한 것은 서로 다른 행동으로 기록하고 해석해줘.
길찾기 버튼을 눌렀다는 이유로 실제 방문했다고 판단하거나, 방문 수가 늘었다는 이유로 매출 효과를 확정하지 말아줘.
점주에게는 자기 가게의 첫 방문·재방문·수집 진행·쿠폰 이용을 이해할 수 있는 정보를 보여줘. 사용자의 세부 이동 경로를 보여주는 방식은 필요하지 않아.
실제 참여 가게가 적거나 아직 없는 상태도 정직하고 완성도 있게 설계해줘. 탐색할 수 있는 일반 장소와 보상 참여 가게를 구분하고, 가상의 실적이나 가게를 운영 성과처럼 사용하지 말아줘.
15. 실제 사용 시나리오로 구현과 품질을 검증해줘
자동 시험과 화면 확인을 함께 수행해줘. 특히 다음 상황이 실제로 처리되는지 확인해줘.
- 같은 이름의 다른 지점, 같은 건물의 여러 점포, 층과 출입구가 다른 가게를 정확히 찾는 상황.
- 영업 중이지만 캠페인은 종료된 가게, 휴게시간·임시 휴무·자정 이후 영업처럼 상태가 달라지는 상황.
- 위치 권한 없이 탐색하는 사용자와 정확도가 낮은 위치를 받은 사용자.
- 지도 이동·필터 변경·상세 진입·외부 길찾기·앱 복귀 후 선택과 탐색 상태를 유지하는 상황.
- 매장에서 코드 입력이나 확인 도중 통신이 끊겼다가 재시도하는 상황.
- 이미 처리된 방문·쿠폰을 다시 요청하거나 직원 권한이 바뀐 상황.
- 수집품이 없는 첫 사용자부터 방문·획득·게임·꾸미기·전시까지 이어지는 상황.
- 지도나 경로 API가 실패했을 때 다른 방법으로 가게를 찾는 상황.
실제 지도 검증에서는 선택한 제공자의 지도와 실제 좌표가 표시되는지 확인해줘. 합성 좌표나 응답을 사용한 시험은 별도로 표시해줘.
확인 가능한 실제 장소로 지도 위치와 목적지 연결을 시험하되, 그 장소를 승인 없이 참여 가게로 게시하거나 실제 방문·보상을 생성하지 말아줘. 현장 확인은 권한과 동의가 확보된 가게에서 진행해줘.
주요 화면은 변경 전후를 남기고, 지도 조작과 상세 패널, 방문 흐름, 네 게임, 코인 감상, 장착과 공유처럼 정지 이미지로 판단하기 어려운 부분은 실행 과정도 확인해줘.
새 네이티브 연동은 웹이나 개발 환경에서만 동작하는 것으로 끝내지 말고, 실제 배포 대상 빌드에서의 동작과 설정을 검증해줘.
지도 키나 외부 계정 설정이 없어 실연동을 확인하지 못하면 가능한 구현과 독립 검증을 먼저 완료해줘. 어떤 설정이 있어야 어떤 검증을 마칠 수 있는지 구체적으로 남기고, 가짜 응답으로 동작한 것을 실제 지도 연동 완료라고 보고하지 말아줘.
16. 자율적으로 큰 개편을 진행해줘
최신 상태에서 중요한 문제와 선택한 방향을 간단히 정리한 뒤, 구현과 검증을 이어서 진행해줘.
일반적인 설계, 화면 재구성, 데이터 모델과 API 보완, 리팩토링, 자산 제작, 지도 연동과 검증 방식은 스스로 결정해도 돼. 더 좋은 방법이 있으면 위 예시보다 그 방법을 선택해줘.
이번 요청은 UI 수정만이 아니라 실제 지도와 실사용 기반을 만드는 전반적인 제품 개편이야. 이를 위해 필요한 범위를 앱·웹·서버·점주 도구까지 함께 다뤄줘.
작업을 내부적으로 여러 단계나 병렬 작업으로 나누는 것은 괜찮아. 대표 화면이나 첫 단계가 끝났다는 이유로 전체 범위를 중단하지 말고, 핵심 흐름이 연결될 때까지 이어서 진행해줘.
기존 사용자의 보유 물건과 권리, 방문·쿠폰의 신뢰성, 직원 권한, 계정·지갑 보안, 운영·시연 데이터의 구분은 유지해줘. 새 가게 데이터와 구조 변경에는 필요한 마이그레이션·호환·복구 방안도 마련해줘.
추가 비용이 발생하는 계약, 별도 계정 접근, 실제 점주 동의, 공개 출시처럼 내 선택이나 외부 조치가 꼭 필요한 사항만 핵심 쟁점과 추천안을 정리해서 물어봐줘. 일반적인 개발 선택을 세부 단계마다 다시 확인할 필요는 없어.
기존 승인 예산이 있으면 그 범위에서 진행하고, 예산이 없는 유료 자원을 임의로 결제하지는 말아줘. 외부 설정이 막혀도 독립적으로 가능한 작업은 계속 진행해줘.
완료 후에는 무엇을 추가했는지 나열하기보다 실제 사용이 어떻게 달라졌는지를 중심으로 정리해줘.
현재 코드·설치본·서버의 기준, 실제 지도와 가게 데이터의 연결, 개선된 방문·보상 경험, 게임과 현실의 관계, 주요 디자인 전후, 수행한 검증과 남은 확인 사항을 구분해서 보고해줘.
최종적으로는 사용자가 실제 지도에서 가게를 고르고, 현실에서 어렵지 않게 찾아가 방문을 확인받고, 그 경험으로 얻은 수집품을 갖고 싶고 보여주고 싶어지는 서비스를 만들어줘.
현실에서 사용할 수 있는 정확성과 편리함, 수집형 서비스로서의 매력, 앱과 디자인의 완성도를 함께 높이는 것이 이번 작업의 목표야.
