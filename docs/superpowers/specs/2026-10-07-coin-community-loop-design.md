# 가게 코인·방 탐험·시리즈 보상 설계

사용자는 2026-10-07 피드백을 비판적으로 선별·발전시켜 구현하도록 요청했다. 기존 UI 전용 범위에서 이번 보상/커뮤니티 변경은 별도 브랜치로 확장한다. 기존 보유 코인·캐릭터·방문·NFT 권리는 삭제하지 않는다.

## 채택한 흐름

1. 상점의 기존 캐릭터 뽑기는 이름과 설명을 정확히 고친다. 모든 결과는 다음/건너뛰기 입력을 기다린다. 개봉 연출만 시간으로 진행한다.
2. 가게 뽑기권은 가게·등급(브론즈/실버/골드/플래티넘)·이벤트·발행된 풀에 묶인다. 마일리지 구매는 코인을 바로 지급하지 않고 한 장의 소비권을 지급한다. 사용하면 그 고정 풀에서 코인 한 개를 얻는다. 미보유 전용 필터가 없어 중복이 수량으로 남는다.
3. 풀은 기존 점주 발행 수집품의 publication/grade를 참조한다. 다른 가게의 수집품이나 제거된 미디어는 등록할 수 없다. 양의 정수 가중치를 확률로 공개한다. 발행 후 구성/가격/제한/기한을 바꾸지 않고 새 풀로 발행한다. 판매 중단은 가능하지만 발급된 정상 티켓의 사용 권리를 보존한다.
4. 구매 기간·사용 만료·1인 구매 제한·전체 발행 상한을 서버가 검사한다. 계정 잠금과 요청 ID로 구매/차감/사용/중복 응답을 원자적으로 처리한다. 새 코인에 NFT 발행권이나 가짜 방문을 붙이지 않는다. 기존 방문 수집품도 시리즈 진척에 포함한다.
5. 방은 기본 비공개. 별도 공개 동의 후 랜덤 탐험 후보가 된다. 공개 취소·계정 삭제·현재 약관 미동의·양방향 차단은 조회/방문/방명록을 막는다. 공개 응답에는 계정 ID·수령권 ID·방문 시각·위치·개인 목표를 넣지 않는다.
6. 방명록은 먼저 정해진 칭찬 도장(포근해요/멋져요/다시 올게요)으로 구현한다. 자유 글 대신 작성자 삭제·방 주인 숨기기·신고·차단을 제공한다. 방당 하루 한 도장과 계정별 쓰기 제한을 둔다.
7. 방 방문 마일리지는 실제로 집계되는 방문 이력이 있는 고객에게 다른 공개 방 하루 첫 다섯 곳만 각 2P, 총 10P. 자기 방·같은 방 반복·차단/비공개는 지급하지 않는다. 기존 마일리지 원장/계정 잠금을 재사용한다.
8. 코인 시리즈는 운영자가 실제 publication/grade 목록과 동의받은 점주의 쿠폰 조건으로 발행한다. 기본 세트와 모든 프리즘 세트의 진척을 함께 보여준다. 캠페인 기간 동안 계정당 한 번, 수령 당시 가능한 가장 높은 혜택을 발급한다. 코인은 소모하지 않는다. 기본 쿠폰 수령 후 두 번째 프리즘 쿠폰을 중복 지급하지 않는다.
9. 실제 쿠폰은 점주 동의 문서·명시된 발행 상한·사용 기한 없이는 등록 불가. 사용 처리에는 기존 고객 신원 QR·점포 직원 권한·만료·자기 사용 방지·멱등 처리를 재사용한다. 하이레/윤스쿡/고씨네와 1000원은 피드백 예시이며 운영 데이터로 만들지 않는다.

## 화면과 운영

상점/받은 권리에서 가게 뽑기권 화면, 도감에서 코인 수량과 시리즈 목표, 놀이/내 방에서 월계 방 탐험으로 연결한다. 기존 캐릭터 뽑기를 가게 뽑기권으로 표시하지 않는다. 실제 API의 빈/로딩/오류를 그대로 표시한다. 새 풀·시리즈 발행/판매 중지·티켓 지급은 기존 관리자 권한을 사용하는 API로 제공하고 형식/절차를 문서화한다. 점포와 동의 조건이 없으면 빈 상태가 정상이다.

## 경계·검증

추가 의존성 없음. 운영 DB seed/공개 배포/실제 쿠폰 발행 없음. migration 0059는 가게 뽑기/시리즈, 0060은 공개 방. 삭제 처리에 두 시스템의 개인정보를 포함한다. 신규 기능의 API 계약·PG 동시성/멱등/기한/차단·모바일 파서/복구·타입/lint/build·실기 기본 화면을 각각 검사한다. 실제 점주 수용·쿠폰 사용·진동 체감·공개 배포를 코드 시험과 구분한다.
