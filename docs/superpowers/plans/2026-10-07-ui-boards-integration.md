# 전체 고객 UI 실제 구현 계획

> **For agentic workers:** Use the approved native subagent execution lanes below. Scope stays at the assigned files; report interface changes before editing shared surfaces.

**Goal:** 23개 시안의 67개 화면 상태를 기존 실제 데이터와 연결하고 탐색→방문→획득→도감→전시→이웃→가게 흐름을 검증한다.

**Architecture:** 기존 Expo 화면·토큰·API를 확장한다. 기존 코인 원장, 방문 권리, 친구, 놀이 기록을 보존한다. 서버가 소유권·공개 범위·거래를 검증하며 화면은 실제 조회와 명확한 빈/실패 상태를 제공한다.

**Tech Stack:** Expo 57 / React Native 0.86 / TypeScript / Node / PostgreSQL. 새 의존성 없음.

**Spec:** `docs/superpowers/specs/2026-10-07-ui-boards-integration.md`. 첨부 PDF 23쪽, manifest와 수정 프롬프트. 보드별 추적은 `docs/UI_BOARDS_STATUS_2026-10-07.md`.

## 공통 제약

- 다섯 탭: 탐색·도감·홈·놀이·상점. 이웃은 탐색, 리롤은 도감.
- 원본 미리보기 PR #396의 합성 상태를 운영에 넣지 않는다. 콘텐츠 자산 재사용은 가능하며 UI는 실제 컴포넌트다.
- 일반 뽑기권은 기존 코인을 유지한다. 리롤은 별도 거래이며 정책 확인 전 소모하지 않는다.
- NFT 진행·완료의 코인은 리롤 제외. 실패/장기대기 상태는 서버 확정 상태를 기준으로 판단한다.
- 방문 1·3·5회 권리, 게임·친구·방문 보상을 임의 변경하지 않는다. 새 가구 가격/지급은 사용자 결정 또는 서버 카탈로그가 필요하다.
- 모든 조회·변경은 기존 인증·삭제 계정·동의·차단 검사를 유지한다. 동일 가게 이웃은 유효한 공통 방문만 사용하고 정확한 가게 방문 시각이나 위치를 노출하지 않는다.
- 기존 slots/theme/layout 데이터는 읽을 수 있게 유지한다. 신규 필드는 추가·기본값 방식으로 이행한다.
- 작은 화면·큰 글씨·키보드·안전 영역·다크 테마·동작 줄이기를 지원한다.

## 검토 초점

1. 직접 URL/방 ID를 통한 공개 범위 우회, 친구 해제·방문 취소·차단 후 접근.
2. 구매·뽑기·리롤 요청 중 종료/네트워크 실패/재시도에서 중복 차감·중복 지급 방지.
3. 코인 출처가 방문 권리/가게 뽑기/등급 뽑기일 때 중복 집계 및 NFT 보호 오류.
4. 빈 계정·삭제/철회된 콘텐츠·목록 저장 경합에서 기존 데이터 보존.
5. 편집 취소/뒤로가기·게임 중 이동·폰트 확대에서 저장과 주요 행동 접근.
