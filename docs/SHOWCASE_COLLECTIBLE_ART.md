# 가상 점포 수집품 그림

가상 점포 A·B·C의 보상권을 구분해 보여주는 **시연 앱용 카드 그림**입니다. 실제 제휴 음식점이나 이미 발행된 NFT의 이미지가 아닙니다.

## 적용 범위

- 이미지 제작: 사용자가 앱 사용을 승인한 기존 MassCOM 마스코트 그림을 시각 참고로 하여 imagegen으로 A·B·C 각 1장을 새로 생성했습니다. 이미지에 점포명·실제 메뉴·가격·NFT 소유·발행 문구를 넣지 않았습니다.
- 앱 표시: `showcase-local-merchant`와 `-b`·`-c`의 정확한 점포 ID에서만 해당 그림을 선택합니다. 서버가 반환한 **본인 보상권**이 있을 때만 도감 카드에 나타납니다. 이름이 비슷한 운영 점포나 미방문 점포에는 붙이지 않습니다.
- 상태: 카드의 `APP · 수집 완료`와 `실제 NFT` 상태는 서버 데이터로 별도 표시합니다. 그림 자체는 NFT 발행·소유권·거래 가치를 증명하지 않습니다.
- 외부 지갑: [Base Sepolia 실증 메타데이터](nft-metadata/base-sepolia-proof/1.json)에는 현재 `image`가 없습니다. 이번 앱 자산은 IPFS/메타데이터에 등록하지 않았으므로 외부 지갑의 썸네일 완료라고 주장하지 않습니다.

## 서버 게시물(Issue #322)

시연 호스트 시드(`host-seed-command`)는 가상 점포 A·B·C 캠페인마다 이 그림으로 수집품 게시물을 하나씩 붙입니다(`apps/api/src/showcase/store-collectibles.ts`). 서버 한도(완성 이미지 변 512px·썸네일 160px)에 맞춰 같은 PNG를 줄인 JPEG가 `store-collectible-art.ts`에 들어 있고, 새 그림이 아닙니다. **Issue #333부터 게시물은 목표 1·3·5회에 브론즈·실버·골드 세 등급을 잇습니다.** 그림은 세 등급이 같고(새 그림 자료 없음), 고객 화면이 등급별로 그리는 등급 이름·동작(실버 `shine`, 골드 `sparkle`과 한 번 터지는 `sparkles`)·인사말만 다릅니다. 이미 걸린 게시물이 점주가 만든 것이거나 이미 3등급이면 건드리지 않고, 시드가 직접 넣은 옛 단일 등급 게시물(등급 하나 `체험`)만 재시드가 새 3등급 게시물로 한 번 갈아 끼웁니다(이미 받은 수집품은 옛 스냅샷 그대로). 두 번 돌려도 같습니다. 이 시드 뒤 받는 보상권부터 `/collection`에 `artwork`가 붙고, 시드 전에 받은 보상권에는 붙지 않습니다. 도감 카드의 앱 내장 그림 선택(위 "앱 표시")은 그대로입니다.

## 실제 점포·온체인 이미지로 확장할 때

1. 해당 점포의 참여·상호/시각 자료 사용 범위와 마스코트 원본의 앱·공개 웹·NFT 이용 권리를 확인해 기록합니다. 사용자 제공 그림의 원본 권리 확인은 아직 남았습니다.
2. 점포 ID별 아트와 1·3·5회 고정 보상 관계를 확정합니다. 실제 없는 메뉴·제휴·방문 실적을 그리지 않습니다.
3. 개인정보·주문번호·정확한 식사 시각이 없는 이미지/JSON을 공개 저장소에 올리고 영구 주소를 검증한 뒤 `image` URI를 메타데이터에 연결합니다. 기존 발행 토큰의 `tokenURI`가 가리키는 자료를 바꾸거나 재발행하는 일은 별도 검토 대상입니다.
4. 실제 Android 도감과 외부 지갑 양쪽에서 이미지, 앱 수집 상태, 체인 최종 완료 상태를 각각 검증합니다. 메인넷 배포·자산 이동·일반 공개는 이번 작업 범위가 아닙니다.
