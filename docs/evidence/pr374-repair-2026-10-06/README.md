## 회귀와 실제 데이터 검사

API 513/513, 모바일 1,673/1,673, 사이트 508/508, 실제 PostgreSQL 전체 497 중 494 PASS·3 SKIP·0 FAIL. API 타입·빌드, 모바일 타입·lint, 접근성 의미·개인정보·지갑 경계 검사도 통과했다. PostgreSQL의 호스트 전용 3개 시험은 별도 격리 환경을 요구해 로컬 SKIP이며 원격 CI에서 별도 실행한다. 독립 코드 검토는 APPROVE, 설계 검토는 CLEAR이고, TypeScript 언어 서비스로 변경된 75개 TS/TSX 파일의 구문·의미 진단이 없음을 확인했다.

실패 회귀 후 통과한 조건은 이전 A 세션의 늦은 401 이후 B의 푸시·대기 친구 링크 유지, 양방향 대기 선물의 수신 우선 조회, 정상·재시도 식사 답장의 응답자 SENT 관점, 잘못된 달력 날짜 400, 새 구매 가능 여부와 독립된 기존 요청 재확인이다. 친구 관계 삭제가 발송 승인보다 먼저 완료되면 새 대기 우편 푸시를 막고 기존 우편·보상은 남긴다. 이미 승인한 외부 발송은 취소 가능한 것으로 주장하지 않는다.

## 실제 UI와 구매 복구

기존 방문 코드 서비스로 만든 9번 방문·수집품 6개·마일리지 950에서 브론즈 세 번과 실버 세 번을 실제 화면으로 개봉했다. [첫 결과](first-draw.png)처럼 추가 마일리지·옷·캐릭터와 확정 꾸미기가 함께 표시된다.

마지막 실버 상품은 서버 POST가 커밋한 뒤 로컬 프록시에서 응답만 끊었다([유실 기록](lost-response-proof.json)). 해당 등급은 3/3 소장이 되어 새 구매가 비활성화됐지만 [기존 결과가 복구됐다](lost-response-recovered.png). 원장은 구매 6건·차감 총 900이며 잔액 246으로, 중복 차감이 없다([검사](recovery-ledger-proof.json)). 이 실행에서는 복구된 결과가 자동으로 표시됐다. 명시적 재확인 버튼의 조건·원래 요청 ID·계정 전환은 별도 실제 컴포넌트/복구 회귀에서 검사했다.

새 그림의 후드를 실제 소장 의상으로 선택·저장한 뒤 [부엉이·모자·대표 코인과 같은 공간](hoodie-studio.png)을 확인했다. 다른 합성 계정의 [친구 공간](hoodie-friend-studio.png)에도 같은 착용이 표시된다. [실제 저장한 피드 PNG](hoodie-feed.png)는 1,482,228바이트이며 동일 옷을 포함한다. 그림 선택·착용·공유의 공통 합성을 사용하고 이름 첫 글자를 옷 그림으로 쓰지 않는다.

의상 atlas는 1254×1254 RGBA, 2×2 중 앞치마·후드·스카프 세 칸과 빈 칸이다. 프롬프트·생성 도구·투명 여백 검사는 `apps/mobile/assets/images/experience-quality/clothing-SOURCES.md`를 따른다. 기존 원화·배지·장비와 운영/시연 데이터 경계는 유지했다.
