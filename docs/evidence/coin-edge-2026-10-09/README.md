## 재현과 저장 계약

1. `COLLECTIBLE_QA_PORT=4193`을 환경 변수로 지정해 `node tests/fixtures/collectible-qa-server.mjs`의 합성 점주 fixture를 실행하고 /merchant/에서 프로젝트를 만든다. 이번 실행은 별도 seed로127.0.0.1:4193을 사용했다. 로컬 fixture는 실제 API·DB 게시 검증을 대신하지 않는다.
2. 사진 편집 단계에서 크기·경도·확대를 조절한다. 코인 만들기에서 실버·양각을 선택하면 테두리도 실버이며 기본 스티커는 없다. 직접 넣은 기존 스티커는 보존된다.
3. 회전·움직임·재질·오라를 따로 설정한다. 재생/정지와 수동 각도, 재질 강도0/100을 비교한다. 결과 단계에서 자동1/3/5 보상을 확인하고 로컬 캠페인에 게시한 다음 재열기한다.
4. `COLLECTIBLE_RELIEF_QA_PORT=4194`·`COLLECTIBLE_RELIEF_QA_UPSTREAM=http://127.0.0.1:4193`을 환경 변수로 지정해 `node tests/fixtures/collectible-relief-qa-server.mjs`를 실행한다. /coin-edges/는 제품 renderer를 가져와 모양·등급·두께24조합을 그린다. 각도90°/110°와 유리 마스크·72각도 벤치마크를 비교한다.

## 성능과 검증 경계

[동일 프로젝트 벤치마크](performance.json)는 최대 두께48·톱니·양각80·프리즘·불꽃65의72각도5°간격을 새로 계산한다. texture640/output512 중앙값88.5ms·P95 103ms, 재생 설정256/256 중앙값63.6ms·P95 90.3ms다. 반복 bitmap 깊이 합성을 연속 측면 경로로 바꾸고, 프리즘 픽셀 중복 계산·매 프레임 큰 JSON 복제·버퍼 크기를 줄였다. 최적화 전후32개 사진 픽셀 비교는 완전히 같았다.

**최악 조건의 새 각도 계산은 여전히50ms를 넘는다.** 캐시된 반복 재생과 처음 계산을 구분하며 모든 기기의 부드러운 재생·30/60FPS를 보장하지 않는다. 계측된 Canvas 메서드 중 getImageData 비용이 컸다. GPU 전체 시간을 재는 자료는 아니다. Android 실기 성능은 추가 검수 대상이다. 시간 누적을 재생 중에만 진행해 정지·숨김·움직임 줄이기 후 각도/오라 시간 점프를 방지했다.

최종 시험과 CI 상태는 [TEST_STATUS](../../TEST_STATUS.md)에 기록한다. API·앱 typecheck, 변경 앱 lint, 웹/계약 회귀와 읽기 전용 리뷰를 수행한다. 앱 전체 worklet 검사에서 잡힌 불꽃 경로 호출은 UI 프레임에서 경로 문자열을 미리 만들고 각 불꽃의 props가 공유 값만 읽도록 수정했다. 기존 검사 규칙과 helper의 worklet 선언은 유지했으며 로컬 앱 전체2112/2112를 확인했다. 첫 CI의 API625/625·PostgreSQL541 PASS/기존3 SKIP과 수정 후 전체 CI는 구분한다. 운영 서버 배포·실계정 점포 게시·Android 실기 검수는 이번 후속에서 실행하지 않았다. API와 웹은 기존 D-096 배포 조건에 따라 함께 전환한다.
