**처음 상태로 시작:** 시연 Preview 22 설치본에서 다음 순서로 시작합니다.

1. 시연 앱 첫 화면에서 "로그인 없이 바로 체험"을 누릅니다. 24시간 임시 계정이며 내 체험 가게의 사장님 화면도 포함됩니다.

3. 체험을 다시 처음부터 보여 주려면 임시 체험 계정의 내 정보에서 "체험 처음부터 다시"를 누릅니다. 로그아웃 뒤 새 체험 계정으로 시작하므로 매번 새 상태입니다.

2026-10-05 main `db28003`의 일일 seed 작업 설치·실행·검증을 완료했습니다: `systemd-analyze verify` 무출력, 수동 실행 `Result=success`, 저널 `SHOWCASE_SEED_STEP_SUCCEEDED`·`BACKUPS_DELETED 0`, `install.sh --verify` PASS([배포 근거](evidence/deployment-db28003-2026-10-05.json)).
발표 전에 [검증 현황](TEST_STATUS.md)에서 설치 여부를 확인합니다. 설치되지 않았거나 실패가 지속되면 만료 전에 수동 재시드 또는 작업 복구가 필요합니다.

**막혔을 때:**

1. "앱 업데이트가 필요해요"가 뜨면 서버가 요구하는 `privacy-2026-10-07`과 APK 내 동의 문구 버전을 대조합니다. 새 API만 먼저 배포하면 옛 test.10/Preview 19 설치본은 `outdated`로 막히며, 옛 APK를 재설치해도 해결되지 않습니다. `/open`이 Preview 22를 가리키는지 확인한 뒤 Preview 22 설치본으로 재동의합니다([배포 절차](OPERATIONS_RUNBOOK.md)).
2. 가게가 안 보이면 새로고침합니다.
3. 체험 시작이 거절되면 잠시 뒤 다시 시도합니다. 서버 기본 상한은 끝나지 않은 동시 체험 300명, 같은 IP(같은 네트워크)의 끝나지 않은 체험 30개입니다(`apps/api/src/showcase/guest-trials.ts`).

Issue #365의 공개 서버 반영과 시연 웹 번들 재빌드는 [배포 근거](evidence/deployment-db28003-2026-10-05.json)에 남아 있고, 이후 시연 API `2d483ed`·Preview 22(`5ca98955`)까지 배포했습니다. Preview 22 설치본의 실제 휴대전화 5분 전체 순서, C 프리즘 수령, 체험 처음부터 다시, 체험 점포 점주 화면은 `NOT_RUN`입니다. 이전 Preview 19는 에뮬레이터에서 임시 체험 진입·동의 화면·동의 거절 후 로그아웃까지만 PASS였습니다.

## 폰 2대 실제 QR 시연 (리허설 전 `NOT_RUN`, B-018)

최신 설치본(운영 test.13·시연 Preview 22)의 실제 휴대전화 실행과 두 기기 QR 흐름은 아직 한 번도 하지 않았습니다([B-018](BLOCKERS.md)). 첫 리허설이 끝나기 전에는 PASS라고 말하지 않습니다. 이 절은 무대에서 쓰기 전에 먼저 리허설하는 절차입니다.

**준비**

- 폰 두 대에 Preview 22를 설치합니다. 폰 A는 점주, 폰 B는 고객입니다.
- 설치한 APK의 SHA-256이 게시 해시와 같은지 확인합니다([Preview 22 릴리스](evidence/showcase-preview22-release-2026-10-08.json)).
- 고객 폰은 발표 직전에 새 체험 계정을 만들고 동의까지 마쳐 방문 0회로 둡니다. 이 계정에서는 미리 "테스트 방문 만들기"를 누르지 않습니다. 오늘 날짜가 먼저 채워지면 실제 QR 방문이 같은 날 두 번째가 되어 세지지 않을 수 있습니다.
- 점주 폰은 Google 로그인 → 동의 → 점주 역할 → 가상 점포 A → "방문 확인"까지 열어 둡니다. "방문 확인 권한이 없어요"가 뜨면 점주 체험 권한 승인을 먼저 받습니다.
- 리허설에는 무대용과 다른 체험 계정을 씁니다.

**순서**

| 단계 | 폰 | 화면과 확인할 점 |
| --- | --- | --- |
| 1 | 고객 | "방문 인증" → "내 2분 식별 QR". QR과 남은 시간이 보입니다. |
| 2 | 점주 | "① 고객 QR 찍기"로 고객 폰의 QR을 촬영합니다. |
| 3 | 점주 | "② 고객 확인" |
| 4 | 점주 | "③ 방문 코드". 방문 코드 QR과 만료 시간이 보입니다. 코드 문자열이 화면 어디에 있는지 적어 둡니다. |
| 5 | 고객 | "1 · 코드 확인"에서 방문 코드 QR을 촬영합니다. |
| 6 | 고객 | "2 · 방문 확정"에서 가게와 캠페인을 확인하고 확정합니다. |
| 7 | 고객 | "3 · 방문 완료". 도장, 봉투, 브론즈 수집품이 나옵니다. |

촬영이 안 되면 방문 코드 문자열을 고객 폰의 "수령 코드" 칸에 입력합니다. 같은 방문 코드로 한 번 더 시도해도 방문이 늘지 않아야 합니다. 1단계부터 7단계까지 걸린 시간을 초 단위로 재 둡니다.

**안 될 때**

1. 점주 확인이나 고객 확정(2~6단계)이 끝내 안 되면 고객 폰의 "테스트 방문 만들기"로 방문을 보입니다. "실제 QR 대신 시연용 방문 기록"이라고 말합니다.
2. 네트워크가 끊기면 발표장 Wi-Fi → 핫스팟 순서로 바꿉니다. 둘 다 안 되면 노트북 웹 `/play/`로 넘어갑니다. 웹에서는 QR 촬영과 폰 기울임을 쓸 수 없어 "테스트 방문 만들기"로 대신합니다.
3. 시연 서버 자체가 응답하지 않으면 백업 영상을 틀고 영상이라고 말합니다. 지금 있는 영상은 이전 번들 기준 웹 녹화(`demo-flow-390.webm`)이고 두 기기 QR 장면이 없습니다. 리허설이 1~7단계를 통과하면 같은 설치본으로 새로 녹화합니다. 녹화 전에 알림을 끄고, Google 계정 이메일이 보이는 화면과 QR 코드 문자열은 담지 않습니다.
4. 두 기기 QR 흐름은 영상도 없으므로 질의에서는 "아직 실기 전"이라고 답합니다.

## NFT 별도 증거

5분 공개 설치본 시연의 성공 조건에 NFT 등록 완료를 넣지 않습니다. 운영 서버는 `NFT_MINTING_MODE=PREPARING`으로 권리를 기록하고 고객에게 "발행 준비 중"을 표시합니다([D-054·D-055](DECISIONS.md)). 질의가 나오면 [Local Anvil Android·Worker 증거](evidence/phase3-worker-anvil-android.json)와 [Base Sepolia 증거](evidence/base-sepolia-deployment.json)를 각각 해당 환경의 발행·복구 근거로 제시합니다. 이를 공개 운영 발행, 메인넷 등록 또는 현장 지갑 수용으로 확대하지 않습니다. 실제 지갑 주소·개인키·복구 문구는 발표 화면에 노출하지 않습니다.

## 뽑기(상점) 시연

방문을 인증하면 쌓이는 마일리지로 가게 친구를 뽑는 흐름([Issue #298](https://github.com/2026-KW-HACKATHON/27_MassCOM/issues/298), 안내는 [Issue #332](https://github.com/2026-KW-HACKATHON/27_MassCOM/issues/332))을 시연 앱에서 보여 줍니다. 이 구역은 시연 앱 기준이고, 운영 앱에는 "테스트 방문 만들기"가 없습니다.

1. **테스트 방문 만들기(showcase):** 방문 인증 탭의 "테스트 방문 만들기"에서 가상 점포를 고르고 버튼을 누릅니다. 실제 QR·점주 코드 없이 가상 점포 방문이 기록되고 바로 확정됩니다.
2. **방문 완료 카드의 마일리지:** 카드에 이번 방문으로 실제 늘어난 마일리지가 "+150 마일리지 적립"처럼 보입니다. 앱이 규칙을 따라 계산하는 값이 아니라 방문 전·후 상점 요약의 적립 합계 차이라서, 서버가 센 만큼만 나옵니다(처음 가는 가게의 첫 방문은 방문 50 + 첫 방문 100 = 150이라 이 예가 됩니다). 합계가 늘지 않은 방문(같은 날 두 번째 방문 등)과 복구된 방문, 전·후 값을 읽지 못한 방문에서는 이 줄이 빠집니다. 이어서 "보유 N마일리지"와 "실버 수집품까지 N번 남았어요 (같은 가게는 하루 1번)" 같은 다음 등급 안내가 나오고, 카드 아래 "상점에서 뽑기" 버튼이 상점 탭으로 바로 이어 줍니다. 상점 요약을 읽지 못하면 "보유"·"적립" 줄만 빠지고 방문 결과는 그대로입니다.
3. **상점 탭 → 등급 선택 → 뽑기:** "마일리지로 캐릭터 뽑기" 구역에서 브론즈·실버·골드 중 하나를 고르고 "뽑기"를 누릅니다. 값은 브론즈 100·실버 200·골드 400마일리지이고, 정본은 서버 응답입니다. 잔액이 모자라면 버튼이 꺼지고 이유가 보이며, "남은 N종 중 하나를 같은 확률"이라는 공개 문구가 구매 전에 항상 보입니다.
4. **대표 캐릭터 지정:** 뽑기 결과 화면, 또는 "가게 친구" 목록에서 가진 친구를 눌러 대표로 설정하면 홈 화면 아바타에 보입니다. 같은 친구를 한 번 더 누르면 대표를 해제할 수 있습니다.

**하루 한 번 규칙과 시연의 차이:** 운영 앱에서는 같은 가게를 한국 날짜 기준 하루에 한 번만 방문으로 셉니다(D-006). 시연 앱의 "테스트 방문 만들기"는 시연 전부 체험(#333, D-068)에 따라 같은 가게의 아직 세지 않은 가장 최근 날짜(최대 29일 전, 캠페인 시작 이후)로 기록되므로, 같은 가상 점포를 연달아 눌러도 1·3·5번째 방문이 모두 세어져 브론즈·실버·골드(가상 점포 C는 프리즘) 수집품까지 같은 날 닿습니다. 시연 서버의 마일리지에는 체험분 100,000이 더해져("시연 체험 마일리지 포함") 등급과 횟수에 관계없이 뽑기를 시연할 수 있습니다. 방문 완료 카드의 "+N 마일리지 적립"은 실제 적립분(방문 전후 상점 요약 차이)이라 체험분은 들어가지 않습니다.

**발표 전 확인:** 새 시연 계정으로 가상 점포 A 또는 B에 테스트 방문 5번 → 도감에서 브론즈·실버·골드 수집품 3개(같은 그림, 등급 이름·움직임·인사말이 다름. 가상 점포 C는 5회에 골드 대신 프리즘) → 상점에서 골드 뽑기 → 대표 캐릭터 지정까지 실제 시연 앱에서 한 번 걸어 보고 결과를 기록합니다. 이미 1·3·5회 보상을 받은 계정은 등급이 새로 생기지 않으므로 새 계정을 씁니다.

이 구역은 코드와 단위 시험으로 쓴 것이고 실제 기기 시연은 아직 하지 않았습니다(`NOT_RUN`, [검증 현황](TEST_STATUS.md)).

## 시연 전부 체험(#333)

시연 서버(시연 앱)에서만 며칠을 기다리지 않고 브론즈·실버·골드·프리즘 수집품·배지 상자·쿠폰·뽑기를 모두 시험할 수 있습니다.

- **수집품 등급:** `테스트 방문 만들기`를 같은 점포에서 5번 누르면 방문이 오늘부터 하루씩 앞선 서로 다른 날로 세어져(오늘 포함 최대 30일, 캠페인 시작 전으로는 가지 않음) 1회 브론즈·3회 실버·5회 수집품(A·B는 골드, C는 프리즘)이 차례로 나옵니다. 그림은 세 등급이 같고 등급 이름·동작(실버 반짝임, 골드 반짝임과 한 번 터짐, 프리즘 무지개빛 재질)·인사말이 다릅니다. 계정당 테스트 방문은 시간당 60회입니다.
- **마일리지:** 상점에는 시연 체험 마일리지 100,000P가 더해져 골드까지 여러 번 뽑을 수 있습니다(상점에 "시연 체험 마일리지 포함" 표시). 보너스를 나중에 빼면 쓴 만큼 잔액이 음수가 되어 더 사지 못합니다.
- **알아 둘 점:** 이미 3회·5회 보상권을 받은 계정은 다시 받지 못하므로 새 시연 계정으로 시험합니다. 방문 날짜가 계정 생성·동의보다 앞설 수 있고, 친구에게는 어제 이전 날짜의 방문이 하루 지연 없이 바로 보입니다. 점원 화면의 "오늘" 방문 목록에는 오늘 날짜의 방문 하나만 보입니다(옮겨진 방문은 취소할 수 없는 지난 날짜).
- **취소 주의:** 점원 화면에서는 오늘 날짜의 방문만 취소할 수 있고, 테스트 방문 중 오늘 날짜는 가장 먼저 만든 방문(1회 보상을 낳은 방문)입니다. 이를 취소하면 그 방문이 낳은 1회 보상과 남은 방문 수보다 목표가 큰 보상이 함께 회수됩니다(5번 눌렀다면 1회와 5회). 다음 테스트 방문이 오늘 날짜를 다시 채우면 회수된 보상이 새로 지급되어 저절로 복구됩니다. 회수될 보상이 이미 NFT 발행 요청으로 넘어갔다면 취소는 409로 거절됩니다.
- **운영:** 운영 서버·운영 앱은 이 규칙을 쓰지 않으며 하루 한 번 진행과 실제 적립 규칙이 그대로입니다.
- **배포 뒤 해야 할 일(시연 서버):** 코드를 배포한 뒤 Issue #365의 [시연 호스트 일일 작업](../infra/showcase-host/README.md#보관-기간-정리시드-유지-작업과-로그-순환-issue-253365-d-059)을 설치·한 번 실행·`install.sh --verify`로 확인합니다. 타이머가 매일 성공하면 host seed가 캠페인 종료를 실행 시각부터 30일 뒤까지 늘리므로 만료 전 수동 재시드는 필요 없습니다. 일일 작업이 설치되지 않았거나 타이머 중단·실패가 지속되면 만료 전에 수동 재시드 또는 작업 복구가 필요하며, 이미 끝난 캠페인은 재시드가 거절하므로 시연 DB 백업 후 운영자의 승인된 데이터 복구가 필요합니다. 운영 DB와 기존 방문·보상은 건드리지 않습니다.
- **재시드 뒤 확인(시연 DB, 읽기 전용):** 세 가상 점포 캠페인의 수집품 연결이 3등급 게시물을 가리키는지 확인합니다. 아래 질의가 캠페인마다 한 줄씩 A·B는 `{bronze,gold,silver}`, C는 `{bronze,prism,silver}`를 돌려주면 정상입니다. 옛 단일 등급 게시물을 알아보는 조건(작성자 열이 비어 있음·이름·테마·등급 배열이 정확히 일치)은 하나라도 다르면 건드리지 않고 넘어가는 안전한 쪽이므로, 일치하는 것이 없으면 아무것도 바뀌지 않고 `{bronze}`가 그대로 남습니다. 그 경우 재시드가 실패한 것이 아니니 연결이 어떤 게시물인지 확인한 뒤 판단합니다(점주가 만든 게시물이면 그대로 둡니다).

```sql
SELECT link.campaign_id, array_agg(grade.grade_id ORDER BY grade.grade_id) AS grades
FROM campaign_collectible_publications link
JOIN collectible_publication_grades grade ON grade.publication_id = link.publication_id
WHERE link.campaign_id IN ('showcase-local-campaign', 'showcase-local-campaign-b', 'showcase-local-campaign-c')
GROUP BY link.campaign_id ORDER BY link.campaign_id;
```
