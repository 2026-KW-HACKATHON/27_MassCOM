# 실제 시연 Runbook

## 정상 순서

1. `main` commit과 CI 성공 run을 화면에 준비합니다.
2. Android 홈에서 지갑 없이 DEMO 음식점 목록·상세를 엽니다.
3. 점주 DEMO에서 고객 1인용 코드를 발급합니다.
4. 고객 화면에서 preview 후 redeem하고 방문·앱 수집품 1개, 실제 NFT 0개를 보여 줍니다.
5. 다음 가게 추천 이유와 상세 복귀를 보여 줍니다.
6. 외부 지갑 주소 확인 상태를 보여 주되 송금·approve 요청이 없음을 설명합니다.
7. 도감에서 전체 주소·체인·양도 제한 안내 후 NFT를 접수합니다.
8. Worker 실행 뒤 `NFT 접수 → 등록 완료`와 contract/token ID를 보여 줍니다.
9. 계정 설정에서 삭제되는 것과 남는 것을 보여 줍니다.

## 뽑기(상점) 시연

방문을 인증하면 쌓이는 마일리지로 가게 친구를 뽑는 흐름([Issue #298](https://github.com/2026-KW-HACKATHON/27_MassCOM/issues/298), 안내는 [Issue #332](https://github.com/2026-KW-HACKATHON/27_MassCOM/issues/332))을 시연 앱에서 보여 줍니다. 이 구역은 시연 앱 기준이고, 운영 앱에는 "테스트 방문 만들기"가 없습니다.

1. **테스트 방문 만들기(showcase):** 방문 인증 탭의 "테스트 방문 만들기"에서 가상 점포를 고르고 버튼을 누릅니다. 실제 QR·점주 코드 없이 가상 점포 방문이 기록되고 바로 확정됩니다.
2. **방문 완료 카드의 마일리지:** 카드에 이번 방문으로 실제 늘어난 마일리지가 "+150 마일리지 적립"처럼 보입니다. 앱이 규칙을 따라 계산하는 값이 아니라 방문 전·후 상점 요약의 적립 합계 차이라서, 서버가 센 만큼만 나옵니다(처음 가는 가게의 첫 방문은 방문 50 + 첫 방문 100 = 150이라 이 예가 됩니다). 합계가 늘지 않은 방문(같은 날 두 번째 방문 등)과 복구된 방문, 전·후 값을 읽지 못한 방문에서는 이 줄이 빠집니다. 이어서 "보유 N마일리지"와 "실버 수집품까지 N번 남았어요 (같은 가게는 하루 1번)" 같은 다음 등급 안내가 나오고, 카드 아래 "상점에서 뽑기" 버튼이 상점 탭으로 바로 이어 줍니다. 상점 요약을 읽지 못하면 "보유"·"적립" 줄만 빠지고 방문 결과는 그대로입니다.
3. **상점 탭 → 등급 선택 → 뽑기:** "마일리지로 캐릭터 뽑기" 구역에서 브론즈·실버·골드 중 하나를 고르고 "뽑기"를 누릅니다. 값은 브론즈 100·실버 200·골드 400마일리지이고, 정본은 서버 응답입니다. 잔액이 모자라면 버튼이 꺼지고 이유가 보이며, "남은 N종 중 하나를 같은 확률"이라는 공개 문구가 구매 전에 항상 보입니다.
4. **대표 캐릭터 지정:** 뽑기 결과 화면, 또는 "가게 친구" 목록에서 가진 친구를 눌러 대표로 설정하면 홈 화면 아바타에 보입니다. 같은 친구를 한 번 더 누르면 대표를 해제할 수 있습니다.

**하루 한 번 규칙:** 같은 가게는 한국 날짜 기준 하루에 한 번만 방문으로 세므로(D-006), 같은 날 같은 가상 점포로 테스트 방문을 반복해도 진행 횟수와 마일리지는 첫 번째만 오릅니다(도감의 방문 기록에는 "방문만 기록"으로 보입니다). 마일리지는 점포마다 첫 방문에 방문 50 + 첫 방문 100 = 150이 붙으므로, 가상 점포 3곳을 한 번씩 방문하면 하루에 450마일리지가 쌓여 브론즈(100)·실버(200)·골드(400) 중 어느 등급이든 같은 날 뽑을 수 있습니다. 반면 한 가게의 실버·골드 **수집품**(3번째·5번째 인정 방문)은 같은 가게를 서로 다른 날 방문해야 하므로, 시연 앱 전체 접근(#333)이 반영되기 전에는 하루 시연에서 닿지 않습니다.

**전체 접근(#333)이 반영되면:** 시연 앱의 전체 접근([Issue #333](https://github.com/2026-KW-HACKATHON/27_MassCOM/issues/333))이 병합·배포된 뒤에는 같은 날 안에 한 가게의 실버·골드 수집품까지 닿게 할 계획입니다. 그 전까지는 위 하루 한 번 규칙이 수집품에 그대로 적용되며, 발표 전에 실제 시연 앱에서 어디까지 닿는지 한 번 확인해 기록합니다.

이 구역은 코드와 단위 시험으로 쓴 것이고 실제 기기 시연은 아직 하지 않았습니다(`NOT_RUN`, [검증 현황](TEST_STATUS.md)).

## 시연 전 검사

```bash
git status --short --branch
gh run list --branch main --workflow CI --limit 1
bash scripts/check-secrets.sh
bash scripts/check-privacy.sh
```

기기·지갑·API·DB·chain 버전과 DEMO 여부를 발표 시작 전에 기록합니다. 실제 지갑 주소·QR 원문·비밀은 화면 녹화나 발표 자료에 남기지 않습니다.

## 실패 대체안

| 실패 | 즉시 보여 줄 증거 | 말할 경계 |
| --- | --- | --- |
| Android/API 연결 실패 | 저장소 Android 스크린샷과 JSON | 사전 촬영/저장 증거이며 현재 실시간 성공으로 말하지 않음 |
| 지갑 앱 복귀 실패 | `android-wallet-connection.json`, `android-wallet-missing.json` | 수동 복귀 PASS와 자동 복귀 미관측 구분 |
| RPC/Anvil 실패 | `phase3-worker-anvil-android.json`, CI Worker 단계 | 운영/Base Sepolia 성공으로 확대하지 않음 |
| 계정 삭제 API 실패 | `account-deletion-privacy.json` | Local DEMO와 운영 재인증 BLOCKED 구분 |

## 금지

- 개인키·복구 문구·지갑 비밀번호 입력 또는 공유
- 실제 고객 주문·QR·정확한 식사 시각 노출
- 현장에서 mainnet·사용자 자산 이동
- 실패 화면을 편집해 실시간 성공처럼 제시
