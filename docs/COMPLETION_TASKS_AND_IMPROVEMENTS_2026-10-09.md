# 완성 기준과 실행 순서

목표는 기능의 개수가 아니라 방문에서 다음 행동까지 끊기지 않는 경험이다.

> 완성 기준: 음식점 발견 → 방문 인증 → 보상 이해·획득 → 도감·전시 → 다음 방문 선택

사용자가 각 화면을 개별적으로 열 수 있다는 것만으로는 충분하지 않다. 보상이 어디에서 왔는지, 무엇을 얻었는지, 어떤 성취가 남았는지, 다음에 무엇을 하면 되는지가 하나의 흐름으로 설명돼야 한다. 점주도 방문 확인과 실수 복구를 수행할 수 있어야 한다.

## 우선순위와 완료 기준

| **순서**   | **핵심 과제**            | **완료 기준**                                                               |
|------------|--------------------------|-----------------------------------------------------------------------------|
| **최우선** | 방문 자격·보상 규칙 통일 | 모든 획득 경로에 같은 자격 원칙이 적용되고, 소모·지급·기록 변화가 명확하다. |
| **최우선** | 풀·뽑기권 운영 조건 확정 | 확률 갱신, 소진·재충전, 직접 사용·자동 사용을 모순 없이 설명한다.           |
| **최우선** | 핵심 사용자 동선 완성    | 방문부터 결과 확인과 다음 행동까지 안내자 없이 수행할 수 있다.              |
| **높음**   | 코인·획득·도감·마이룸    | 음식점별 정체성과 수집 목표가 보이며 실제 보유·저장 상태에 반영된다.        |
| **높음**   | 실제 기기·점주 검증      | 중복 입력, 중단, 재접속, 큰 글씨에서도 권리와 필수 행동이 유지된다.         |
| **높음**   | 도입·운영·비용 정리      | 누가 준비·운영·비용을 맡고 어떤 가치를 확인할지 설명한다.                   |
| **후속**   | 연합 미션·동행 확장      | 기본 경험을 복잡하게 만들지 않고 새 음식점 탐색을 보완한다.                 |

## 진행 방식

먼저 기획과 기존 동작을 비교해 차이를 기록하고, 핵심 규칙을 정한 뒤 화면과 검증을 연결한다. 시연 기능의 화려함을 높이기 전에 결과 보존과 다음 행동을 완성한다. 정책이 정해지지 않은 기능은 결정 대기 항목으로 관리한다.

**추천안** 보상 재화·상점 종류·화면을 추가하기보다, 방문 자격을 지키는 하나의 보상 체계와 끝까지 이어지는 하나의 경험을 먼저 완성한다.

실행 산출물: 획득 경로 점검표, 핵심 동선 전후 화면, 정책 결정표, 검증 기록. 근거: \[U2\]·\[U3\]·\[R1\].

# 방문 자격과 보상 역할

획득 경로가 달라도 음식점 방문의 의미가 유지되도록 설계한다.

**기획 전제** 해당 음식점의 인정된 방문이 음식점별 코인의 획득 자격을 만든다. 다른 활동은 그 자격을 보완할 수 있지만 대신하지 않는다.

방문 보상뿐 아니라 상점, 가게권 구매, 상자, 추가 뽑기, 교체형 재뽑기, 연합·동행 보상에도 같은 원칙을 적용한다. A 음식점에서 얻은 보상으로 미방문 B 음식점의 코인을 받을 수 있다면 또 다른 우회 경로가 생긴다.

## 보상별 역할과 경계

| **구성**               | **맡길 역할**                | **지켜야 할 경계**                                        |
|------------------------|------------------------------|-----------------------------------------------------------|
| **방문 기반 뽑기**     | 기대감과 선택의 재미         | 확정적인 방문 진행을 대체하지 않는다.                     |
| **N회 방문 확정 보상** | 운과 무관한 진행의 확실성    | 뽑기 결과 때문에 이미 달성한 방문 기록이 사라지지 않는다. |
| **마일리지·가구**      | 과정에 남는 누적 성취        | 미방문 음식점 코인의 우회 획득 수단이 되지 않는다.        |
| **시리즈 완성 보상**   | 한 음식점의 수집 목표        | 필요한 코인·진행·보상을 명확히 보여준다.                  |
| **연합 미션**          | 새 음식점 탐색의 계기        | 방문 횟수만 많은 이용자에게 유리한 구조로 끝내지 않는다.  |
| **동행 보상**          | 함께 방문할 추가 이유        | 혼자 이용하는 사람의 기본 경험을 약화하지 않는다.         |
| **추가·교체형 뽑기**   | 이미 방문한 가게의 수집 보완 | 기존 코인의 유지·소모와 진행 변화를 구분한다.             |

## 획득 경로 점검표에 적을 항목

각 경로에 해당 음식점 방문 필요 여부, 사용할 수 있는 음식점 범위, 소비하는 권리·재화, 지급 결과, 기존 코인 유지 여부, 도감·방문 기록의 변화를 적는다. 예외를 허용한다면 어떤 수집품이 실제 방문을 뜻하는지도 별도로 설명해야 한다.

> 코인을 한 개 더 얻는 것과 음식점을 한 번 더 방문한 것은 다르다. 추가 획득으로 방문 횟수를 늘리지 않는다.

완료 기준: 모든 경로를 따라가도 같은 자격 원칙이 유지되고, 실제 방문과 단순 보유를 혼동하지 않는다. 근거: \[U2\]·\[R1\].

# 음식점별 풀과 뽑기권 운영

모든 이용자가 해당 음식점의 풀을 함께 사용한다는 전제로 운영 조건을 정한다.

**기획 전제** 비복원 추첨으로 지급한 코인은 풀에서 빠지고 남은 구성이 다음 추첨에 반영된다. 뽑기권 보유자는 잔여 구성을 확인하며, 미사용 권리는 발급 후 1주일이 지나면 자동으로 사용한다.

강조할 것은 확률이 계속 높아진다는 약속이 아니라 남은 기회를 이해할 수 있다는 점이다. 일반 코인이 빠지면 프리즘 비율이 높아질 수 있지만, 프리즘이 먼저 뽑히면 낮아질 수 있다. 다른 이용자의 추첨 때문에 조회 시점과 실제 사용 시점의 구성이 달라질 수도 있다.

## 결정해야 할 운영 조건

| **항목**                | **정리할 내용**                                                                     |
|-------------------------|-------------------------------------------------------------------------------------|
| **시작 구성**           | 코인 종류와 수량, 초기화 단위, 구성이 변경되는 절차를 정한다.                       |
| **잔여 정보·확률**      | 갱신 시점과 실제 추첨 기준을 연결한다. 사용자가 보는 수치의 의미를 안내한다.        |
| **희귀 코인 소진**      | 남은 프리즘이 없을 때 획득 가능성을 숨기거나 있다고 표현하지 않는다.                |
| **전체 소진·재충전**    | 재충전 조건과 이미 발급된 뽑기권의 처리 방식을 함께 정한다.                         |
| **1주일 자동 사용**     | 예정 시점, 적용할 풀 상태, 결과 보관 위치, 실패 시 권리 보존·재시도를 정한다.       |
| **직접·자동 사용 중복** | 같은 권리의 결과가 두 번 생기거나 권리만 소멸하지 않도록 확인한다.                  |
| **음식점 확률 표시**    | 기준보다 높은 확률의 판단 기준과 공개 범위를 정한다. 보유자용 상세 정보와 구분한다. |

**추천안** 희귀 코인이 소진됐다는 이유로 임의 시점에 풀을 다시 채우지 않는다. 사용자가 잔여 구성을 보고 판단한다면 변경 규칙도 예측 가능해야 한다.

## 사용자에게 보여줄 정보

권리가 속한 음식점, 사용할 수 있는 조건, 자동 사용 예정 시점, 확인 가능한 잔여 구성, 정보 갱신 시점을 가까이 둔다. 자동 사용된 결과는 나중에 다시 확인할 수 있게 하되 새 추첨처럼 보이지 않게 한다.

완료 기준: 풀 소진·동시 이용·자동 사용 상황까지 하나의 정책으로 설명할 수 있다. 시작 수량·재충전 조건·강조 기준은 확정값이 아니라 결정 과제다. 근거: \[U2\]·\[U3\]·\[R1\].

# 상점과 마일리지 개선안

방문을 대신하지 않으면서 수집의 아쉬움을 보완하는 구조를 제안한다.

## 상자 보상은 추가 뽑기권 중심으로 검토

**추천안** 상자의 기본 보상을 기존 코인을 유지하는 추가 뽑기권으로 정리한다. 이 제안은 아직 채택된 정책이 아니며, 기존의 교체형 재뽑기와 구분해 결정해야 한다.

원하는 결과를 얻지 못한 사용자의 수집을 보완하려는 보상인데, 사용하려면 이미 가진 코인을 잃어야 한다면 새로운 손실 가능성이 생긴다. 같은 “재뽑기”라는 이름으로 서로 다른 행동을 설명하지 않는 것이 중요하다.

| **구분**            | **제안하는 역할**                                                    | **사용 전 안내**                           |
|---------------------|----------------------------------------------------------------------|--------------------------------------------|
| **추가 뽑기권**     | 기존 코인을 유지하고 방문 자격이 있는 음식점에서 한 번 더 획득한다.  | 사용 가능한 음식점·권리 수량·결과 범위     |

**추천안** 먼저 마일리지로 가구·장식을 얻는 경험을 완성한다. 별도의 조각·교환석·중복 전용 포인트를 추가하기보다 기존 재화의 적립·지출·활용을 이해하기 쉽게 만든다.

# 코인 획득과 마이룸 경험

갖고 싶은 물건, 만족스러운 획득 순간, 계속 활용하는 공간을 연결한다.

## 코인 외형과 획득 연출의 목적을 구분

코인의 외형은 “갖고 싶은가”를, 획득 연출은 “얻는 순간이 만족스러운가”를 다룬다. 재질·빛·회전이 정교한 것만으로 음식점별 수집의 의미가 완성되지는 않는다. 이름을 가렸을 때도 가게별 특징이 구별되는지 함께 검토한다.

| **개선 대상**       | **추천하는 방향**                                              | **확인할 장면**                     |
|---------------------|----------------------------------------------------------------|-------------------------------------|
| **음식점별 정체성** | 특징·대표 이미지·색·문양을 수집품에 반영한다.                  | 이름 없이도 구별되는가              |
| **재질과 등급**     | 일반·희귀 보상의 시각적 차이를 명확히 하되 실제 결과와 맞춘다. | 앞뒤·기울기·확대에서 일관되는가     |
| **획득 과정**       | 보상 출처 확인부터 공개·감상·활용까지 한 흐름으로 만든다.      | 가게 코인 획득 경로가 끊기지 않는가 |
| **반복 이용**       | 건너뛰기, 소리·진동·움직임 감소를 지원한다.                    | 연출을 생략해도 결과는 보존되는가   |

> 음식점과 보상 출처 확인 → 개봉 반응 → 코인 등장 → 감상 → 도감 또는 전시

**추천안** 실제 결과와 무관한 희귀 보상 암시나 아슬아슬하게 놓친 것처럼 보이는 표현은 넣지 않는다. 일반 보상도 일관된 완료감을 주고, 결과는 사용자가 확인할 시간을 남긴다.

## 마이룸: 방문 결과가 남는 개인 공간

일반 꾸미기 게임처럼 기능을 계속 확장하기보다 음식점 방문으로 얻은 코인을 전시하는 핵심 동작부터 완성한다. 획득 직후 전시, 기존 전시품 교체, 전시한 코인의 음식점 정보 확인이 자연스럽게 이어져야 한다.

**추천안** 첫 전시에 복잡한 가구 배치가 필수가 되지 않도록 기본 전시대나 간단한 배치 방법을 검토한다. 이는 추가 기능을 크게 늘리기보다 보상 활용까지의 단계를 줄이는 제안이다.

마이룸의 완료 기준은 완성 화면 한 장이 아니다. 실제 보유품으로 배치하고 저장한 뒤 앱을 다시 열어도 상태가 유지돼야 한다. 전시품을 통해 관련 음식점을 확인하는 경로가 없다면 구현된 방문 연결로 설명하지 않고 개선 과제로 둔다.

확보할 자료: 획득 전후, 건너뛰기 후 결과, 첫 전시, 저장·재접속 화면. 근거: \[U2\]·\[R1\].

# 연합 미션·동행과 지역 탐색

같은 음식점의 재방문과 다른 음식점의 발견을 서로 다른 목표로 다룬다.

## 두 가지 방문 흐름

| **흐름**               | **핵심 연결**                                              | **관찰할 행동**                      |
|------------------------|------------------------------------------------------------|--------------------------------------|
| **같은 음식점 재방문** | 방문 → 코인 → 부족한 시리즈 확인 → 다음 방문 목표          | 같은 음식점의 다른 날 방문           |
| **다른 음식점 탐색**   | 다른 수집품·연합 미션 발견 → 새 가게 관심 → 방문 → 첫 수집 | 새 가게 상세 조회와 실제 방문을 구분 |

한 가게에 오래 머무르게 하는 설계가 지역 내 여러 가게로의 방문 분산을 자동으로 입증하지는 않는다. 도감과 시리즈는 같은 음식점의 목표를, 연합 미션은 새로운 음식점을 고려할 계기를 제공하는 방향으로 역할을 나눈다.

## 연합 미션: 작은 목표부터 검증

**추천안** 많은 음식점과 여러 단계의 보상을 요구하기보다 평소 가지 않던 가게를 한 곳 더 고려하게 하는 짧고 명확한 미션부터 검증한다. 참여 음식점·완료 조건·진행·보상을 한눈에 이해할 수 있어야 한다.

연합 미션은 외식 빈도가 높은 사용자에게 더 유리해질 수 있다. 미션을 추가했다는 이유만으로 이용자 간 격차가 줄었다고 설명하지 않는다. 참여 문턱과 기본 꾸미기 경험은 별도로 검토하고, 추가 뽑기권도 방문 자격 원칙을 지켜야 한다.

기존에 코스·여러 가게 탐색 기능이 있는지 먼저 확인하고 활용 가능성을 검토한다. 진행 화면이 존재하는 것과 완료 후 추가 뽑기권까지 연결되는 것은 다른 완료 조건이다.

## 동행 보상: 참가자별 인정 방문이 기준

**기획 전제** 함께 방문하는 경험을 보완하되 각 참가자의 인정된 방문이 확인돼야 한다. 같은 QR을 여러 번 읽은 것만으로 공동 방문을 입증하지 않는다.

**결정 필요** 같은 방문 세션의 범위, 참가자 확인, 중복 방지, 음식점별 풀과 희귀도 강화권의 관계를 정한다. 강화권이 보장하는 것이 무엇인지 명확하지 않다면 먼저 규칙을 확정한다.

**추천안** 혼자 이용하는 사람의 기본 수집 경험을 유지한다. 동행 보상 규칙이 미정이라면 기본 방문·뽑기를 먼저 완성하고 후속 검증 항목으로 남긴다.

완료 기준: 새 가게를 탐색할 이유가 생기면서 미방문 코인 우회 획득이나 참여 강요가 발생하지 않는다. 근거: \[U2\]·\[R1\].

## 지역 문제를 행동 수준으로 확인

“지역 상권 활성화”만으로 필요한 기능을 정하기 어렵다. 이용자가 새 음식점을 선택하지 않는 이유, 다시 방문하는 이유, 음식점 수집품에 관심을 느끼는 조건을 직접 확인한다. 메뉴·가격 정보를 몰라 선택을 미룬다면 코인뿐 아니라 가게 정보와 탐색 화면도 보완해야 한다.

## 점주가 해야 하는 일을 줄이기

> 가게 확인 → 수집품 준비 → 방문 인증 → 실수 처리 → 운영 결과 확인

**추천안** 기본 템플릿과 필수 항목 중심으로 준비 과정을 단순화한다. 점주가 시각 효과와 보상 규칙을 모두 직접 설계하도록 요구하지 않는다. 자주 쓰는 방문 인증과 취소·재발급은 가까운 동선에 둔다.

완료 기준은 설정 메뉴가 존재한다는 사실이 아니라, 설명을 듣지 않은 점주가 자기 가게의 방문을 확인하고 실수를 복구할 수 있는가다. 처리 시간, 오류, 도움 요청, 계속 사용할 의향을 함께 기록한다.

| **연출 건너뛰기·자동 결과 확인** | 연출 생략이나 늦은 확인이 이미 확정된 결과를 바꾸지 않는다.       |
| **전시 저장 후 재실행**          | 저장 상태와 실제 소유 상태가 유지된다.                            |
| **큰 글씨·소리 끔·움직임 감소**  | 필수 정보와 행동에 계속 접근할 수 있다.                           |

## 증거를 남기는 단위

> 행동 전 화면 → 사용자 입력 → 행동 후 상태 → 재접속 후 유지

각 기록에는 기준 빌드, 기기·환경, 사전 조건, 실행 순서, 기대 결과, 실제 결과, 증거 파일, 남은 문제를 적는다. 통과·실패·미실행을 분리하고 실제 실행하지 않은 과제를 통과로 채우지 않는다.

**추천안** 희귀 보상 연출을 보여주기 위해 별도 테스트 상태를 사용한다면 정상 이용의 당첨 사례처럼 제시하지 않는다. 시연용 조건임을 밝히고 일반 이용의 결과와 분리한다.

완료 기준: 핵심 경험의 전후 상태와 중단·중복 상황을 고정된 설치본에서 재현할 수 있다. 기술 상세는 근거 부록에 두고 본문은 사용자가 얻는 신뢰로 설명한다. 근거: \[R1\].

# 현장 검증과 심사 근거

사용자의 반응을 행동으로 확인하고, 각 심사 항목에 맞는 증거를 연결한다.

“재미있다”는 답변만으로 방문 효과를 입증하지 않는다. 규칙 이해, 수집품 활용, 가게 탐색, 실제 방문이 어디에서 연결되고 끊기는지 각각 확인한다. 모집 목표와 실제 참여 결과도 별도로 기록한다.

| **검증 대상**    | **관찰할 내용**                            | **해석상 주의**                       |
|------------------|--------------------------------------------|---------------------------------------|
| **규칙 이해**    | 사용 조건·확률 변화를 자기 말로 설명하는가 | 읽었다는 사실을 이해로 보지 않음      |
| **획득·활용**    | 결과 감상 후 도감·전시로 이동하는가        | 희귀 결과의 반응만 보지 않음          |
| **다음 행동**    | 부족한 코인의 획득 방법·방문 목표를 찾는가 | 상세 조회를 방문으로 세지 않음        |
| **지역 내 탐색** | 새 가게에 관심을 갖고 실제로 방문하는가    | 새 상세 조회와 새 방문을 분리         |
| **재방문**       | 같은 가게에 다른 날 다시 방문하는가        | 앱 재접속과 음식점 방문을 분리        |
| **점주 운영**    | 처리 시간·오류·도움 요청·지속 이용 의향    | 시연 담당자의 숙련도를 대신 쓰지 않음 |

## 네 가지 심사 기준에 남길 근거

| **평가 항목**               | **핵심 근거**                                                                           |
|-----------------------------|-----------------------------------------------------------------------------------------|
| **실현·상용화 가능성 30점** | 도입 과정, 운영 부담, 비용 구조, 실제 참여·사용 의향, 검증 계획                         |

| **지역 문제 적합성 20점**   | 지역 이용자·점주의 실제 불편, 대응 기능, 같은 가게 재방문과 다른 가게 탐색의 구분       |

서비스에서 처음 확인된 방문을 해당 음식점의 생애 첫 방문이나 신규 고객으로 해석하지 않는다. 매출 변화는 비교 기간·표본·외부 요인을 고려한 별도 검증이 필요하며, 기대효과를 실적으로 적지 않는다.
