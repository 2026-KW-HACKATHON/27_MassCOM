# 동네 탐험 배지와 공유

[Issue #212](https://github.com/2026-KW-HACKATHON/27_MassCOM/issues/212)의 첫 구간은 기존 도감의 확인된 방문을 더 이해하기 쉬운 탐험 목표로 보여준다. 다른 게임의 캐릭터·화면·상표는 사용하지 않고 MassCOM의 동네 가게와 기존 마스코트만 사용한다.

| 단계 | 조건 | 사용자에게 보이는 상태 |
| --- | --- | --- |
| 첫 발걸음 | 진행에 반영된 서로 다른 점포 1곳 | 첫 배지와 공유 선택 |
| 두 번째 골목 | 2곳 | 다음 점포까지 남은 수 |
| 월계 탐험가 | 3곳 | 세 번째 배지와 공유 선택 |

같은 점포를 반복 방문하거나 보상 진행에 반영되지 않은 방문은 새 점포 수를 늘리지 않는다. 계산 입력은 로그인한 본인의 도감 응답이며 별도 배지 DB·NFT·발행 작업을 만들지 않는다. 기존 점포별 1·3·5회 앱 수집품과 NFT 정책은 바뀌지 않는다. 운영 점포가 0곳이면 가상의 획득 기록을 만들어 채우지 않는다.

Android 공유 버튼은 획득한 배지에서만 나타난다. 시스템 공유창에 배지 이름과 공개 웹 주소만 전달하고 계정 ID, QR, 방문 날짜·점포 목록, 지갑 주소·거래 정보는 보내지 않는다. Android에서는 공유창 취소와 전송 완료를 구분할 수 없으므로 완료 메시지를 표시하지 않는다([React Native Share](https://reactnative.dev/docs/share)).

시연 앱은 세 점포 목표와 함께 **실제 매장 사용 불가·할인 코드 없음**을 반복 표시하는 쿠폰 예시만 둔다. 운영 앱·웹에는 가상 쿠폰을 보여주지 않는다. 실제 쿠폰 발급은 점주 동의, 누가 비용을 부담하는지, 혜택·기간·발급 상한·계정별 일회성·취소·직원 사용 확인을 먼저 확정하고 서버 거래와 감사 기록으로 구현해야 한다. 현재 클라이언트 배지를 금전적 권리의 판정 근거로 재사용하지 않는다.

기존 파랑·크림·초록 팔레트와 마스코트 스탬프를 사용해 세 단계를 하나의 세로 탐험 길로 묶는다. 큰 글씨에서 줄이 늘어날 수 있게 하고 의미를 색상에만 맡기지 않는다. 이번 구간에 자동 움직임은 없으며 이후 움직임을 추가하면 감소된 동작 설정을 존중한다([W3C 접근성 지침](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)).

소스 검증: 모바일 244/244, 운영 웹 48/48, 모바일 타입·린트·Android 개발 export, 문서 게이트 PASS. [배지 운영 웹](evidence/neighborhood-badges-web-deployment-2026-09-29.json)은 기존 서버에 배포됐고, [Preview 6 시연 APK](evidence/showcase-preview6-release-2026-09-29.json)는 공개 사전 릴리스로 게시됐다. 그러나 APK의 휴대전화 화면·공유창·TalkBack과 실제 쿠폰 사용은 NOT_RUN이다.
