## 2026-10-08 점진적 공개·점주 1인 2역·최소 크기 (Issue #412 T2c, 배포하지 않음)

기준 main `cd01c0d6`(PR #422 병합) 위의 브랜치 `feat/first-use-v2c` 작업이다(T2는 PR #415로 병합됐다). 앱 코드와 문서만 바뀌었고 API·DB·migration은 바뀌지 않았다. 결정은 [D-090~D-091](DECISIONS.md)에 있다(D-088은 PR #422가 쓰고 D-089는 아직 병합되지 않은 PR #420 몫으로 비워 두었다).

점진적 공개: 처음 온 사람은 첫 코인부터 보고 나머지 입구는 필요할 때 드러난다. 단계는 첫 코인 전·첫 코인 뒤·단골 셋이고(두 번째 가게, 인정된 방문 3회, 배지 3단계, 시연 보너스를 뺀 마일리지 200 이상, 쓰지 않은 뽑기권 중 하나면 단골), 홈의 마이룸·전시·상점 카드, 머리글의 마일리지 칩, 도감의 내 공간·동네 놀이 안내가 이 단계에 따라 열린다. 친구·쪽지와 놀이는 사람이 설정 "더 즐기기"에서 직접 켜는 선택이며, 이미 친구가 있는 계정은 켜진 것으로 보고 친구를 추가하면 켠 것으로 기록한다. 경로·데이터·잔액·서버 판정과 다섯 칸 탭은 그대로다. 단계는 앞으로만 가고 기기에 계정별로 남으며 다른 계정 몫은 로그인 때 지운다. 탭 화면의 포커스는 머리글 세 요청뿐이고, 단계를 가르는 `/collection`·`/coin-shop`은 홈 자신의 조회와 방문 수령 직후에만 읽는다. 상세는 [DESIGN](../DESIGN.md)의 Information architecture와 D-090이다.

점주 1인 2역: 시연 앱·로컬 개발 빌드에서 한 사람이 점주 화면과 손님 화면을 오가며 방문을 끝까지 해 볼 수 있다. 점주 화면의 단계 카드(① 열림 ② 손님 QR ③ 방문 코드 발급 ④ 현황 확인)와 "시연: 내 손님 QR로 해 보기", 손님 화면의 "점주 화면에서 이 QR 확인해 보기"가 서버가 방금 발급한 값을 메모리로만 넘긴다. 값은 넘긴 계정에 묶이고 한 번 읽으면 지워지며 만료되고 로그아웃·계정 전환·세션 무효화에서 비워진다. URL·로그·저장소에는 쓰지 않으며 서버가 계속 결정한다(D-091, D-065와 대비). 이 밖에 방문 완료 뒤 마일리지 줄(축하 뒤 표시, 배지 조회가 멈춰도 막히지 않음), 글자 12dp·터치 44dp 최소 크기, 죽은 코드와 개발용 경로(`foundation-preview`·`showcase-tour`) 정리가 들어 있다. `/shop-again`은 지우지 않고 `/shop`으로 리다이렉트해 옛 링크가 계속 열린다.

검증: 모바일 `npm test` 2074/2074, typecheck·lint PASS, 접근성 의미 검사·지갑 표면 검사·CI 연결 PASS(자세한 명령은 [TEST_STATUS](TEST_STATUS.md)). 구현은 Claude Sonnet, 교차 리뷰는 Claude Sonnet과 Claude Opus가 했고 반드시 고칠 것(🔴) 없이 🟠 둘과 🟡들을 반영했다([AI_USAGE](AI_USAGE.md)). 배포·게시는 하지 않았다(소유자 결정 A). 공개 상태는 그대로다: 운영 API·웹 `687427c2`, 운영 test.13, 시연 Preview 22, 시연 `/play/` 번들 `5ca98955`. 이 코드는 다음 빌드부터 사용자에게 닿는다.

## 2026-10-08 API 서버 구조 정리: routes·http·이름 붙은 deps (Issue #412 트랙 T1, 배포 동결)

기준 main `b572184e`(PR #411 병합)에서 시작해 main `b707ed09`(PR #413·#414·#415·#421 병합) 위로 옮긴 작업이다. 브랜치 `refactor/api-deps-routes`에서 `apps/api/src/server.ts`(약 2,600줄이던 요청 처리와 구성 루트)를 나눴고 동작은 바꾸지 않았다. 결정은 [D-088](DECISIONS.md)이다. 구조는 이렇다. `src/routes/*.ts`의 `handleXxx(ctx): Promise<boolean>` 17개를 `server.ts`가 정해진 순서로 부른다(순서가 곧 경로 우선순위). 요청·응답 도우미는 `src/http/*.ts`에 있다. `createApiServer`는 위치 인자 40여 개 대신 이름 붙은 `ApiDeps` 하나를 받는다. 시작 코드의 `Required<ApiDeps>`와 `Required<ExperienceServices>`가 키 누락을 컴파일에서 잡는다. 제한기·계정 해석 래퍼는 `createApiRuntime(deps)`가 서버 인스턴스마다 만든다(모듈 전역 상태 없음).

마무리에서 교차 리뷰의 🟡를 반영했다. `createApiServer`가 받은 deps를 복사해 한 번만 얼리고(`Object.freeze`), 기본값(`trustProxyClientIp`·`webWwwEnabled`·`experienceServices`)을 거기서만 정해 런타임과 경로 처리기가 `??` 없이 같은 객체를 읽는다. 웹 로그인 콜백의 쿠키 응답(실패마다 state 쿠키 지우기와 noindex, 성공 시 [지우기, 세션] 두 쿠키 순서)과 계정 삭제 접수 서비스 두 개의 배선(`webAuth && !showcaseInvites`, `showcaseInvites`의 `SHOWCASE_APP` 출처)을 시험으로 고정했다.

검증: API 단위 597/597(이 작업 전 591, 새 시험 6건), PostgreSQL 전체 524 pass / 0 fail / 3 skip, 요청 처리 본문 `89d7a5e4` 대비 인라인 동등성 1797/1797줄(차이는 로그아웃 블록 위치뿐), 변이 점검 6건 모두 시험 실패, 빌드와 `/health` 부팅 PASS. 교차 리뷰(Claude Sonnet·Claude Opus) 승인, 🔴 0·🟠 0. 자세한 결과는 [TEST_STATUS](TEST_STATUS.md)에 있다. 서버·설치본은 바뀌지 않았고 배포하지 않았다(소유자 결정 A).

남은 것: 위치 인자 `createApiServer`를 흉내 내는 시험 전용 덮개(`apps/api/src/server-test-support.ts`와 `http-test-support.ts`의 `positionalArgs`)는 그것을 쓰는 시험이 남아 있어 두었다. 쓰는 시험이 없어지면 지운다. `postgres/`·`showcase/`의 서비스 파일 39개에 되풀이되는 `BEGIN`/`COMMIT`/`ROLLBACK` 묶음을 `withTransaction` 도우미로 모으는 일은 이 작업에서 하지 않았다(D-088).

## 2026-10-08 첫 사용 경험: 웹 첫 화면·동의·첫 코인·가게 사실 표시 (Issue #412, 배포 동결)

기준 main `b572184e`(PR #411 병합) 위의 브랜치 `feat/first-use-v2` 작업이다. 소유자 2026-10-08 방향 가운데 신규 사용자 첫 코인 흐름과 첫 화면 즉시 반응 부분이다. 앱 코드와 CI 한 줄만 바뀌었고 API·DB·migration은 바뀌지 않았다. 결정은 [D-083~D-087](DECISIONS.md)에 있다.

웹 첫 화면: `apps/mobile/public/index.html`이 번들이 내려오는 동안 보이는 CSS만 쓰는 한국어 대기 안내(다크 모드·동작 줄이기·`<noscript>`)를 `#root` 안에 둔다. 흰 화면이던 구간이다. 웹 번들에서 Reown·WalletConnect·ethers를 뺐다(`.web` 형제 파일과 웹에서만 일어나는 Metro 리다이렉트). 진입 번들이 6,375,429B에서 4,119,372B(약 35% 감소, gzip 1,044,640B)로 줄었고, 번들에 그 문자열이 0건임을 CI가 확인한다. Android는 실제 지갑 모듈을 그대로 쓴다. 소리 플레이어는 배경음 2개를 그리기 화면 첫 진입 때, 웹 UI 소리 7개를 첫 사용자 동작 때 만든다.

동의 화면: 늘 보이는 정확한 세 줄 요약, 접힌 "자세히 보기"(전체 안내), "전체 동의"(일부만 누르면 `mixed`), "개별 확인"이다. 필수 세 가지와 서버로 보내는 값, 약관·개인정보 버전은 그대로다. 요약과 전체 안내(앱·`apps/production-web`)가 `docs/privacy.html`의 보유 기간·공유(친구에게 보이는 정보, 방명록, 점주 방문 CSV)를 빠뜨리지 않도록 맞췄다.

홈·가게·첫 코인: 홈은 요청별로 상태를 채워 하늘 배경·CTA·가게 정보가 다른 요청을 기다리지 않는다. 방문이 없는 사람에게는 서버 추천 또는 참여 가능한 첫 가게를 "처음이라면 이 가게부터" 카드로 보이고, 방이 비었고 수집품이 있으면 "수집품 N개 · 방에 놓기"를 보인다. 가게 카드·상세는 핵심 사실을 먼저, 방문 결정에 중요한 영업·마지막 주문·보상·최소 이용을 항상, 나머지 부족한 정보를 한 번에 모아 보인다. 상세는 "첫 방문 기념 코인"을 먼저, 방문 인정 조건을 서버 규칙과 가게 확인으로 나눠 보인다. 첫 코인을 받는 순간에는 나만 볼 수 있는 빈 방에 한해 "첫 코인을 내 공간에 놓아볼까요?"를 보이며, 앱은 공개 범위를 바꾸지 않는다. 서버가 공개 범위를 조건으로 받지 않아 재조회와 저장 사이의 좁은 창이 남는다(D-086).

접근성: 장식 마스코트는 웹에서만 탭 순서와 접근성 트리에서 뺀다(Android는 라벨과 "눌러서 흔들기" 버튼 그대로). 웹에 `main`과 `navigation`(웹에서만 붙는 "주요 메뉴") 랜드마크를 달았다.

검증: 모바일 `npm test` 1992/1992(PR #414 위로 리베이스한 뒤의 합계, 리베이스 전 이 브랜치 단독 1974), typecheck·lint PASS, 접근성 의미 검사·지갑 표면 검사·CI 연결 PASS, 시연 웹 export PASS. 코드 구현은 Claude Sonnet, 교차 리뷰는 Claude Sonnet과 Claude Opus가 두 차례 했고 지적을 반영했다([AI_USAGE](AI_USAGE.md)). 배포·게시는 하지 않았다(소유자 결정 A). 공개 상태는 그대로다: 운영 API·웹 `687427c2`, 운영 test.13, 시연 Preview 22, `/play/` 번들 `5ca98955`. 이 코드는 다음 빌드부터 사용자에게 닿는다.
