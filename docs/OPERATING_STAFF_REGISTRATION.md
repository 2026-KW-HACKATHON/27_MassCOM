# 운영 직원 등록 절차 (소스 상태)

운영 계정으로 고객 Android 앱에 먼저 로그인한 직원이 `/merchant/`에서 실제 점포를 선택하고 등록 코드를 발급한다. 이 코드는 현재 웹 세션의 계정과 선택한 점포, `STAFF` 역할에만 연결된다. 직원이 관리자에게 신원이 확인된 별도 연락 경로로 코드를 전달하면, 운영 관리자는 `/admin/`의 **같은 점포**에 코드를 입력해 명시적으로 승인한다. 관리자는 직원 이메일이나 Google subject를 입력하지 않는다. 코드를 전달받았다는 사실만으로 신원 확인이 끝나지 않으므로, 관리자와 직원은 승인 전에 별도 운영 절차로 서로를 확인해야 한다.

코드는 128비트 난수 22자이며 15분 뒤 만료된다. DB에는 SHA-256 해시만 저장하고 승인·재발급 후 다시 쓸 수 없다. 승인·회수와 감사 행은 각각 한 트랜잭션이다. 회수는 `STAFF`만 바꾸고 `OWNER`를 건드리지 않는다. 회수는 점포 행 잠금으로 QR 발급·재발급과 직렬화된다. 계정 삭제는 미승인 요청을 지우고 감사 계정 ID를 가명화한다.

현재 운영 배포 범위: 운영 웹 등록 요청, 관리자 승인·목록·회수, 고정 `/merchant/` OAuth 복귀, Host·Origin·JSON 검사, 비색인·비캐시. [직원 등록](evidence/operating-staff-deployment-2026-09-28.json), [고객 QR 확인·방문 수령 QR](evidence/operating-merchant-qr-deployment-2026-09-28.json), [첫 발급 응답 손실 후 재발급](evidence/operating-merchant-reissue-deployment-2026-09-28.json)은 각각 별도 커밋·CI·백업으로 배포했다. **실제 직원 승인, 실제 점포·실계정 브라우저와 두 휴대전화의 촬영·수령·재발급은 검증하지 않았다.** 재발급 응답까지 끊겼을 때 서버 상태 조정은 후속이다. 기존 인증된 모바일 점포 API 경로는 그대로 있으며, 승인된 직원 계정과 활성 점포·캠페인이 있어야 방문 발급이 성립한다.
