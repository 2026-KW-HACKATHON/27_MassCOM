# 첨부 고객 UI 구현·검증 기록 (Issue #399)

23개 보드와 67개 화면 상태를 기존 앱에 연결했다. 화면별 경로와 구현 근거는 [67상태 대응표](UI_BOARDS_STATUS_2026-10-07.md), 확정 정책은 [요구사항과 같은 대화의 결정](superpowers/specs/2026-10-07-ui-boards-integration.md)을 따른다. 이 문서는 로컬 구현·검증 기록이며 운영 배포 완료 보고가 아니다.

## 변경 범위

- 공통 의미색을 아이보리/민트로 바꾸고 프로필·소개·실제 마일리지·우편/설정을 압축 헤더로 연결했다. 홈은 실제 마이룸, 보유 뽑기권, 방문 목표, 친구/방문 인증을 먼저 보여 준다. 작은 높이/큰 글씨에서는 주요 행동을 위로 올린다.
- 다섯 탭 순서를 유지하며 테마/색/아이콘 미리보기·적용·취소를 계정별 기기 저장에 연결했다. 이웃은 탐색, 리롤은 도감에 속한다. 문맥 화면은 하단 바 높이를 콘텐츠 밖에 확보한다.
- 도감은 가게→코인 종류→네 등급과 실제 수량/출처를 보여 준다. 가게권 개봉, 일반 뽑기, 코인 회수 리롤, NFT 요청은 서로 다른 권리로 유지한다. 새 코인은 대표 설정과 마이룸 전시로 이어진다.
- 가구 카탈로그/구매/보관함/배치는 동일 자산 ID를 사용한다. 배치·회전·보관·벽/바닥·저장/취소, 버전 충돌, 저장 중 새 편집 보존을 구현했다. 긴 편집 화면은 가구·전시·동행·목표/공유로 나눴다.
- 나만/친구/공통 방문 가게 이웃을 실제 방 조회와 반응 API에도 적용한다. 방문자/답방, 선택적 친구 추가, 한 줄 방명록/반응/신고/숨김/차단을 연결하고 물리적 가게 방문 시각·실시간 위치는 노출하지 않는다.
- 친구/우정/우편/초대 응답, 프로필/탐험 여권, 설정/동의/계정 기능을 기존 서버에 연결했다. 네 게임의 준비·일시정지·재개·종료·결과/기록은 기존 점수/보상 규칙을 유지한다.
- React Native Web0.21.2 색상 구독 패치를 기존 patch-package에 추가해 실행 중 테마 전환에서 일부 영역만 이전 테마로 남는 문제를 고쳤다. 새 의존성은 없다.

## 시각·동작 확인

390×844 웹에서 홈 빈 상태, 한 줄 소개 저장과 복귀, 하단 바 우드 미리보기/적용, 놀이 준비·실행·일시정지를 확인했다. 라이트↔다크 왕복은 헤더/본문/탭의 실제 계산 색으로 함께 확인했다. 마이룸의 첫 편집본은 콘텐츠가 약8,972px로 길어 목적별 모드와 위쪽 저장/취소로 수정했다. 최종 웹 비교에서 홈91점·마이룸 편집90점이다. 기본 편집 콘텐츠는 약1,384px로 줄었으며 저장/취소가 첫 화면에서 보인다. 게임 종료 확인·허브 복귀, 편집 이탈 계속하기·저장, 방문 코드→보상 개봉→도감→전시→공통 가게 이웃→관련 가게 상세까지 브라우저로 직접 확인했다. 가상 점포의 게시 시각 누락과 도감 개봉 뒤 홈 미개봉 수 갱신을 수정했다. 모든67상태 또는 네이티브 실기 전체를 직접 조작했다고 주장하지 않는다.

실물 검증도 별도 로컬 가상 고객·가상 점포를 사용했다. 이전 비디버그 설치본을 동일 서명 개발 APK로 갱신하고, 최신 공유 worktree의 Metro 번들을 실제 기기에서 실행했다. 시험 방문 C의 정상 160×160 이미지가 봉투와 공개 카드에 표시되었다. A의 잘못된 1px 시험 PNG는 로컬 fixture 문제로 분리했으며 앱 소스로 숨기지 않았다. 개인정보 재확인은 시험 계정에만 적용했고 실제 계정 동의나 생산 인증을 대신하지 않는다.
