## D-093 가게 사이를 잇는 코스와 서버 판정 장면 (Issue #412 T4 A, 2026-10-08)

소유자 방향 3번과 이번 구현 지시를 근거로 팀이 서로 다른 가게 2–4곳을 상황(AFTER_MEAL: 식사 후 들르기 좋은 곳, TAKEOUT: 포장해서 가져가기 좋은 곳, OTHER: 함께 들러볼 만한 곳)에 맞춰 코스로 구성한다. 단계마다 가게·방문 목표 1/3/5회·조각 이름·점주 참여 동의 기록 참조를 고정한다. 한 코스 안에서 조각 키는 고유하며 점주 참여 동의 참조는 단계마다 서로 달라야 한다. AI가 점포 이야기나 신규 고객 실적을 만들지 않는다. 같은 날 방문을 강요하지 않는다.

진행은 코스의 `[counts_from, ends_at)` 기간에 발생한 취소되지 않은 유효 방문(`visit_events`)을 가게별로 세어 판정한다. 게시할 때 `counts_from`은 기간 시작 이후로 고정되므로 게시 전 방문은 포함되지 않는다. 리롤은 단계 완료를 되돌리지 않는다. 방문 취소로 유효 방문 수가 목표 아래로 내려가면 단계는 미완료가 되고 이미 열린 장면은 STALE로 표시한다. 장면 열기는 서버가 한 트랜잭션에서 모든 단계를 다시 확인하며 계정·코스 advisory lock과 고유키로 중복을 막는다. 클라이언트 완료 주장값을 받지 않는다. 완성에 마일리지·쿠폰·새 코인을 지급하지 않는다.

초안 → 점검 → 게시 → 중지 순서다. 점검은 공개 운영 점포, 점주 확인 위치(OWNED), 가게 간 직선거리, 선택한 한국 시각의 영업시간, 업종 조합, 현재 공개 ACTIVE 캠페인의 목표·모집 여유를 확인하고 라벨이 있는 스냅샷으로 저장한다. 도보 제공자 호출을 재사용할 독립 함수가 없어 v1은 직선거리만 사용한다. 점검은 실시간 영업 또는 실제 도보 경로의 증명이 아니다. 게시에는 한 시간 이내 점검과 각 단계의 점주 참여 동의 참조가 필요하며 게시 순간에도 적격성을 다시 확인한다. 시연·게스트 체험 점포는 운영 게시 대상에서 제외한다. 게시 후에도 점포가 ACTIVE·공개 상태를 잃거나 현재 공개 ACTIVE 캠페인이 끝나거나 단계 목표를 제공하지 않으면 그 단계는 UNAVAILABLE로 표시하고 완료로 세지 않는다. 앱은 “지금은 이용할 수 없는 가게예요”라고 안내한다. 이용할 수 없는 단계가 하나라도 있으면 새 장면 열기는 불가능하되 이미 열린 기록은 유지한다. v1에서는 코스가 PAUSED 또는 ENDED이면 이미 연 사용자도 장면에 접근할 수 없다.

v1 장면은 팀이 정한 `scene_key` 이름과 각 가게에서 받은 코인 썸네일로 구성한다. 새 그림을 만들지 않는다. 추천은 진행 중인 코스의 다음 미완료 가게를 우선하며 기존 추천 reasonCode 세 값은 유지하고 선택 `course` 필드만 보탠다. 정원 마감 가게는 추천에서 제외하고 코스 상세에는 자리 없음을 표시한다. 조회는 도감처럼 선택 놀이 동의 없이 허용하며 장면 열기 POST는 현재 놀이 동의를 요구한다.

migration `0072_courses.sql`은 새 표 세 개·가드·감사 action을 더하는 추가 전용이다. `0068_campaign_purposes.sql`의 `CAMPAIGN_PURPOSE_SET`도 감사 CHECK 합집합에 보존한다. 운영 보상·수령·취소·0034 획득 트리거는 수정하지 않는다. 시연 코스 fixture는 시연 DB seed에서만 만든다. 계정 삭제와 삭제 계정 보존 정리는 코스 열기 기록도 제거하고 큐레이터 계정 ID를 가명 처리한다. 과거 API 이미지가 남긴 큐레이터 ID도 삭제 원장에 따라 제한된 배치로 재처리한다. 배포하지 않았다(소유자 결정 A). Studio 장면 배치는 후속 범위다.
**남은 위험(열림):** 상한이 없으므로 탈취된 민터 키는 계약이 일시 중지될 때까지 활성 시리즈에 잠긴 NFT를 제한 없이 발행할 수 있다. 총 NFT 가스 지출을 제한하는 장치는 민터 잔액 하한과 건당 수수료 상한뿐이다. 소유자가 상한 해제를 결정했지만 이 두 위험에 대한 별도 통제 결정은 없다.

월계1·2·3동의 실제 음식점 상호·주소·좌표를 공공 상가정보에서 가져와 시연 전용 점포로 제공한다. 운영 환경에는 seed하지 않는다. 원본은 소상공인시장진흥공단 상가(상권)정보(공공데이터포털), 2026-06-30 스냅샷이며 포털의 이용허락범위 표시는 “제한 없음”이다. 원본 487곳 중 월계역(37.6341068, 127.0589231) 거리순으로 30곳을 고른다. 구내식당·유흥주점은 제외하고 중분류별 최대 6곳, 같은 상호는 중복하지 않는다. 원본의 영업 여부는 확인하지 않았으며 모든 `open_status_confirmed` 값은 false다. LOCALDATA 교차 확인도 하지 않았다. 실제 영업 중이라고 표시하지 않는다.

이 점포는 실제 가게의 참여를 뜻하지 않는다. 각 레코드는 `is_demo = true`와 `showcase-wolgye-<SEMAS id>`로 식별하고, 공개 시연 상세의 `merchant.story`에 아래 문장을 그대로 표시한다.

> 실제 가게 정보(소상공인시장진흥공단 상가정보, 2026-06-30 기준)로 만든 시연 점포예요. 이 가게는 MassCOM에 참여하지 않았어요.

메뉴, 가격, 영업시간, 소개, 점포 이야기 등 원본에 없는 사실은 채우지 않는다. 영업시간은 `UNKNOWN`으로 둔다. 코인 그림은 기존 A/B/C 시연 템플릿을 분류별로 결정적으로 재사용하며 새 AI 그림을 만들지 않는다. 전역 시연 배너는 유지한다.

자료 파일의 attribution은 `출처: 소상공인시장진흥공단 상가(상권)정보(공공데이터포털, 2026-06-30 기준)`이다. 원본 스냅샷은 시간에 따라 낡을 수 있다. selector는 현재 `data_date`가 `2026-06-30`인 자료만 허용한다. 갱신할 때는 새 원본을 검토하고 날짜 검사를 통과하도록 바꾸며, attribution과 정확한 날짜 고지도 함께 검토·갱신한 뒤 `node scripts/build-showcase-wolgye-stores.mjs <full JSON>`으로 목록을 재생성한다. 선택 결과와 빠지거나 새로 들어온 상호, 중복, 영업 상태, 기존 ID의 변경 메타데이터를 검토·조정한 뒤 seed한다. 기존 seed ID의 정규 데이터가 달라졌으면 조용히 덮어쓰지 않고 트랜잭션을 롤백한다. 이 선택 스크립트만으로 기존 seed가 자동 교체되는 것은 아니다. 갱신은 시연 DB 이름 가드가 적용되는 seed 경로로만 한다.

## D-102 회전·움직임 분리와 런타임 오라/옆면 (새 PR, 2026-10-09)

**소유자 직접 결정(USER_CONFIRMED):** 기존 PR을 이어 수정하지 않고 새 PR로 만든다. 편집기는 붓 크기·경도를 두고 더 크게 작업할 수 있어야 한다. Flame 같은 이글거리는 효과는 움직임·재질과 함께 보되 새 **오라** 항목으로 둔다. 재질 효과 강도는 실제로 보여야 하며, 미리보기는 재생/정지 한 버튼으로 전환한다. 표현 스타일은 애니메이션보다 위에 둔다. 회전과 움직임은 서로 따로 있어야 한다. 코인 후면도 정면처럼 회전 실시간 조명·반짝임이 보여야 하며, 옆면 테두리는 실제 동전 같은 고정 무늬를 쓰되 얇은 코인에서도 괜찮아야 한다.

**구현 선택(PROPOSED, 에이전트):** 3단계는 표현 스타일(원본·흑백·음각·양각) 다음에 애니메이션과 효과를 둔다. 애니메이션과 효과 안에서는 `회전` 탭을 기본으로 열고 `움직임`, `재질 효과`, `오라`, `목소리`, `살아 있는 그림`, `가게 이야기`를 별도 탭으로 둔다. 회전은 `rotationSpeed`와 수동 각도, 움직임은 기존 once/loop motion JSON을 담당한다. 2단계는 새 사용자에게 기본 스티커를 자동 삽입하지 않고, 새 점포 추천 motif·메뉴 문구도 스티커로 만들지 않는다. 저장된 사용자 스티커는 계속 보존한다. 오라는 `flame` 효과의 색·강도·속도만 저장하고 별도 이미지 타일을 만들지 않는다. 재질 강도0은 no-op이다. 후면12종은 기존 고정 이미지를 재사용하며 회전 각도별 조명·프리즘 glint를 런타임에서 다시 합성한다. 프리즘이 아닌 테두리도 `baseColor` 단색 대신 현재 등급 금속색 gradient를 쓰게 하여 실버 림이 브론즈색처럼 보이는 문제를 막는다. 옆면은 모양별 144칸 reeded edge를 고정 규칙으로 만들고, 투영 간격이 2px보다 작거나 얇은 두께에서 과밀해지는 홈은 줄이거나 생략한다. 앞면/후면 이미지를 새로 대량 저장하는 대신 기존 스프라이트·고정 뒷면·metadata 저장 형식을 유지한다. 실제 재생은 웹·앱75ms/도×배율로 맞추며 모든 움직임과 함께 회전한다. 재생 버퍼256px·정지/내보내기512px, 프리즘 픽셀 계산 공유와 연속 측면 경로로 비용을 줄인다.
