# 수집·게임 경험과 점주 직접 운영

[Issue #371](https://github.com/2026-KW-HACKATHON/27_MassCOM/issues/371), 기준 main `aae64d88973caea2f5ee1b1f13a44173e96e55bb`, 브랜치 `feat/collection-merchant-completion`. 기존 방문·도감·코인 재질·미니게임·공간·점주 제작기를 재사용해 아래 연결을 추가했다. 이 문서는 코드와 로컬 검증을 설명하며 공개 설치본·운영 배포 결과는 아니다.

## 사용자 흐름

홈의 전시에서 대표 동행·장착 배지·대표 코인·팩 진행·원하는 꾸미기·다음 가게·알림함을 찾는다. 공간에서 장착한 모자·가방·소품·포즈·장식은 서버에 저장되고 현재 방문·게임 성취 조건으로 다시 검사한다. 취소된 방문에 기대는 꾸미기는 실제 장착·친구 공개에서 제외한다.

카페 산책·빵집 골목·밤시장 탐험 팩은 기존 브론즈/실버/골드 캐릭터 가격 100/200/400 마일리지를 사용한다. 같은 등급 미보유 캐릭터 하나와 미보유 꾸미기 하나를 지급한다. 캐릭터는 남은 종류마다 `1/남은 종류 수`이며 꾸미기는 모자→소품→장식의 확정 순서다. 꾸미기 확정 지급을 추첨 확률로 표시하지 않는다. 등급별 세 번 개봉하면 세 친구와 세 꾸미기가 모인다. 서버 원장에 보너스를 고정해 재시도와 재접속에 같은 결과를 돌려주며 마일리지 환급·재뽑기권 순환은 추가하지 않았다. 과거 캐릭터 원장에도 같은 테마를 연결한다.

배지는 탐험·단골·꾸준한 방문 및 네 게임의 성취를 구분한다. 타이밍은 정확한 연속 배치 3회, 짝 찾기는 오답 1회 이하로 6쌍 완성, 배달은 12구간 무충돌, 주문은 연속 정답 8회가 목표다. 서버가 실행 seed·입력으로 성취를 재계산한다. 실행 입력은 30일 뒤 정리해도 영구 기록의 성취·꾸미기 해금은 계정 삭제까지 유지한다. 게임은 방문 마일리지·쿠폰·방문 코인을 발급하지 않는다.

친구 공간은 유지 중인 관계와 계정 잠금을 확인하고 관계를 다시 검사한다. 공유하는 것은 장착 모습과 공개 수집품·가게 정보이며 원하는 목표·계정·방문 시각·보상권 ID는 공개하지 않는다. 친구 수집품에서 가까이 보기·가게 확인·내 방문 목표 저장으로 이어진다.

스토리는 상단 270px·하단 384px를 비우는 자체 구도로 문구를 중앙에 배치하며 실제 파일의 OCR 좌표를 확인했다. 공식 플랫폼 승인이나 외부 게시 확인은 아니다. 공간 공유는 1080×1350 피드와 1080×1920 스토리 PNG, 약 4초 움직이는 영상이다. Android 10 이상은 PNG를 Pictures/MassCOM에, H.264 MP4를 `Movies/MassCOM`에 저장한 뒤 공유 화면을 연다. 웹은 지원되는 실제 MP4/WebM 인코더와 일치하는 확장자를 사용한다. 저장·취소·사용 불가를 구분하고 공유 화면을 연 것과 외부 게시 완료를 구분한다. 대표 코인·선택한 모습·배지가 같은 장면에 반영된다.

## 점주 흐름

별도 점주 웹의 가게 선택 아래 캠페인 연장·직원 관리·기간별 CSV가 연결된다. ACTIVE OWNER만 자신의 실제 점포를 관리한다. 활성 일반 캠페인을 30일 또는 90일 연장하고, 현재 종료일과 바뀔 날짜·운영 동의를 확인한다. 종료일 비교·요청 ID·감사 기록으로 동시 변경과 재시도를 처리한다. 종료·일시정지·비공개 등 일반 조건 밖의 캠페인은 기존 운영자 경로로 처리한다.

직원은 기존 Google 로그인과 15분 등록 코드를 사용하고 점주가 코드 승인으로 활성화한다. 점주는 방문 확인과 쿠폰 처리 권한을 따로 변경하고 접근을 해제한다. 기존 STAFF에는 두 업무가 기본 허용된다. 소유권 승격은 기존 운영자 경로이며 직원 UI로 다른 가게에 접근하지 못한다. 실제 업무 거래가 현재 권한을 검사하므로 이미 열린 화면에서도 변경·해제가 반영된다. 계정 삭제와 권한 변경은 같은 계정 잠금 순서를 지키고 감사 기록의 원계정 식별자를 지우거나 가명 처리한다.

CSV는 KST 날짜 기간과 화면의 인정 방문 SQL을 공유한다. 취소·같은 날짜 추가 인정·직원 본인 발급·체험 가게를 같은 기준으로 제외한다. 방문일·방문 시각(KST)·캠페인·방문구분(`처음 확인된 방문`/`다시 확인된 방문`, MassCOM 앱 기록 기준이며 평생 첫 손님이라는 뜻이 아니다)·수집보상과 쿠폰 발급·사용 건수를 내보내며 손님 열과 원계정 ID는 넣지 않는다. 한글 UTF-8 BOM·인용/줄바꿈·수식 방어, 제한 기간·행 수·DB 실행 시간으로 다운로드를 보호한다. 실제 방문과 쿠폰 이용의 효과이며 매출 효과로 표시하지 않는다.

## 알림 설정과 실제 연결

앱 안 알림함은 OS 푸시 허용 여부와 관계없이 보상·쿠폰 만료·캠페인 만료를 보여준다. 종류별 설정과 푸시 선택은 서버에 저장한다. 기기는 유효한 Bearer 로그인 세션에 연결하고 토큰 갱신·로그아웃·계정 전환을 처리한다. 만료/해제된 세션으로는 발송하지 않는다. 원본 보상·쿠폰·캠페인을 스캔해 멱등 알림을 만들며 잠금·기한·재시도·FCM 오류·토큰 폐기·90일 정리를 처리한다. 연장·취소·사용·점주 해제 뒤에는 알림의 원본 상태를 다시 검사해 오래된 안내를 숨기고 발송하지 않는다. 수령 대상 수집품/쿠폰을 누르면 현재 계정이 가진 대상의 화면만 연다.

실제 Android 수신을 확인하려면 다음 설정을 적용한다.

1. 운영 `kr.masscom.wolgye`, 시연 `kr.masscom.wolgye.demo`, 개발 `kr.masscom.wolgye.dev` 중 시험할 package와 일치하는 Firebase Android 앱의 `google-services.json`을 준비하고, 해당 빌드의 `MASSCOM_FIREBASE_GOOGLE_SERVICES_FILE`에 절대 경로를 넣는다.
2. 같은 Firebase 프로젝트의 API 서버 환경에 `FCM_PROJECT_ID`, `FCM_CLIENT_EMAIL`, `FCM_PRIVATE_KEY`를 넣는다. 키는 서버에만 두고 저장소/앱/로그에 넣지 않는다. PEM 줄바꿈 또는 이스케이프된 줄바꿈을 지원한다.
3. migration0044–0049과 개인정보 버전 `privacy-2026-10-05`를 포함한 API·처리방침·앱을 함께 준비한다. 최신 dev/release 앱에서 테스트 계정 로그인→알림 설정→권한 허용→기기 연결→실제 보상/쿠폰 알림 생성→수신→대상 이동을 확인한다.
4. 발송 응답 성공, 단말 알림 표시, 알림 터치 이동을 각각 기록한다. 모의 FCM 성공은 실제 기기 수신의 증거가 아니다.

연동 근거: [Expo SDK 57 알림](https://docs.expo.dev/versions/v57.0.0/sdk/notifications/), [FCM HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api), [FCM 오류](https://firebase.google.com/docs/cloud-messaging/error-codes).

## 배포·호환과 검증

새 migration은 원장·프로필·기기/알림·감사·성취를 추가한다. 기존 캐릭터 보유권과 방문/쿠폰 권리는 유지하며 0048은 이전 API의 원장 INSERT도 지원한다. 코드 롤백 때 사용자 데이터를 담은 표·열과 적용 기록을 삭제하지 않는다. 새 데이터의 삭제/알림 정리 작업은 최신 코드로 계속 실행해야 한다. 운영 앱의 고객 전용 경계와 시연 데이터 격리를 유지한다.

현재 실행 결과와 실제 이미지·영상은 [검증 증거](evidence/collection-completion-2026-10-05/README.md), [시험 현황](TEST_STATUS.md)을 따른다. 공개 배포와 최신 공개 APK, 물리 기울임·효과음/진동 체감·실제 FCM 수신은 로컬 구현/에뮬레이터 시험과 별도다.
