## 재현 가능한 검사 명령

다음 명령은 저장소 루트에서 실행할 수 있다. 전체 테스트 결과는 위 기록 시점의 상태이며, PostgreSQL 통합은 완료됐고 site 전체 집계는 신규 1개 테스트를 포함해 다시 실행해야 한다.

```sh
(cd apps/mobile && npm test)
(cd apps/mobile && npm run typecheck)
(cd apps/mobile && npm run lint)
(cd apps/api && npm test)
(cd apps/api && npm run typecheck)
(cd apps/api && npm run build)
(cd apps/api && npm run test:postgres)
```

`test:postgres`는 지정한 `TEST_DATABASE_URL`로 실행되므로 전용 `_test` 데이터베이스를 준비하고 병렬 전체 통합 실행을 피해야 한다. 격리된 UI 하네스는 `apps/api`에서 `./node_modules/.bin/tsx ../../.tmp/real-world-qa/harness.mjs`로 시작하도록 기록돼 있으나, 이 명령은 지정된 전용 QA DB를 재시드한다. 그 외 운영 DB를 대상으로 실행하지 않는다.

## 배포·운영 전 선행 조건

1. 전체 site 테스트를 다시 실행해 새 JSONB 회귀 검사를 포함한 결과를 기록한다.

3. 자격 증명을 외부 저장소에 노출하지 않고 TMAP 계정·키·요금 한도·약관·SDK private AAR 배포 조건을 확인한다. 모바일 앱 공개 식별자용 `EXPO_PUBLIC_TMAP_MAP_APP_KEY`와 서버 호스트의 `TMAP_REST_APP_KEY`를 각각 설정해야 하며, 서버 키와 별도로 각 환경의 map key 적용을 점검한 뒤 지도·POI·보행 경로를 라이브로 검사한다.
